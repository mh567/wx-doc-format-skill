# T01 手工编号标题：去编号保标题

依赖：无。本包唯一工单。

## 背景

见 `README.md`。定案方向为用户 2026-09-16 裁定的 A（去编号保标题）。

## 工作项

### 1. 角色优先级

`scripts/wxdf/semantics/structure.py` 的 `collect_structure_candidates` 调整分支顺序：显式标题（含文档标题）样式先裁决；受保护分支只在理由不属于 `manual_heading_marker` 时决定角色。标记理由仍写入角色候选的附加证据，供决策账本追溯。

其余文本型理由（API 标签、API 路径、日期版本、法规条款、公式、IP 地址）优先级不变，`docs/execution-v3/acceptance.md` 的 L11 与 `tests/test_issue4_acceptance.py` 钉住这一点。带角色的受保护结论（`note`、`numbered_note`、`code_block`、公式原子）同样保持原优先级。判据来源为 `note_semantics.source_note_role`，不动它的规则。

### 2. 标题文本清理

同一模块新增内容候选：已定级标题（`role` 为 `heading` 或 `title`）且 `text_utils.strip_heading_marker_prefix(text)` 与原文不同时，发布 `update_node_content`，写入去标记后的 `inline_content`。标记只消费段首出现的字符，标题内部的 marks 保留。

`role == "title"` 一并处理：Markdown 首个带标记的 H1 会先被判为 `title`，其交付文本同样不得带手工编号（验收清单第 11 项），已退役的 Markdown 读取器对标题也做同样的去标记。

去标记后文本为空、或标记跨过行内不可消费对象时：不发布内容候选，源文本保留，分别产出 `heading_marker_only_text` 与 `heading_marker_not_consumed` 记录。

### 3. 影子等价审计的角色读取

`scripts/wxdf/semantics/equivalence.py` 的 `_candidate_roles` 原本对每个节点取最后一条候选的 `proposal.value` 当角色。结构模块现在为同一节点发布第二条不带 `role` 的写，会把内容载荷读成角色，等价审计随即报 `role_mismatch`。改为只认带 `role` 的候选。该函数只有测试调用方，无生产调用方。

### 4. 治理文档同步

定案后把两条规则写入 `AGENTS.md` 决策 10：显式标题样式先于 `manual_heading_marker`；已定级标题的交付文本不含手工标记，标记词表归 `text_utils.strip_heading_marker_prefix` 单一所有者。
