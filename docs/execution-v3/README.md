状态：T00 至 T16 已完成源码实现与本机验证，外部平台和页面视觉验收仍按 status.json 单列。适用仓库：私有 wx-doc-format-skill-dev 的本地 dev 工作区。

## 1. 首次启动

1. 完整读取仓库 AGENTS.md、docs/development-workflow.md 和 [方案 3.0](../modular-pipeline-design-v3.md)。
2. 读取 [状态清单](status.json)、[接口落地约定](contracts.md) 和 [验收矩阵](acceptance.md)。
3. 核对当前文件与方案摘要。当前编制时 HEAD 为 cd68200d521146508c306ca7f62f32590d729587，版本 0.12.19；这是观察值，实施时重新核对。
4. 按 status.json 选择第一个依赖全部 done 的 pending 任务，从 T00 开始。只读当前任务卡及其列出的源码，避免同时修改后续任务。
5. 每次改 .py 前声明具体路径与分工，例如“→Codex 设计 / →Claude 实现 / →Claude+Codex 审查：scripts/wxdf/model.py、tests/test_modular_ast.py”。
6. 按任务卡先添加能失败的合同/行为测试，再实现并验证。新模块测试可因模块缺失先失败，不能将 SyntaxError 或无关导入失败当作正确红灯。
7. 写任务证据并更新状态后进入下一任务。一次完成一个可验证任务，持续推进授权范围；工具或上下文中断时保存 next_action。

角色遵循 AGENTS.md：Hermes 总控及 Git，Codex 设计/审查，Claude Code 实现。角色名不等于当前工具已连接这些 agent，禁止伪报已委派或已复审。若实际执行者身份与仓库分工不同，应先记录明确的执行安排；未获得安排时可继续只读设计核验。

## 2. 文件与修改边界

新增代码统一放在 scripts/wxdf/，保留现有 scripts 下稳定入口。新文件列表是计划创建项，尚不存在不属于仓库故障。Python import 使用 wxdf 包，遵循当前测试将 scripts 加入 sys.path 的方式。

任务卡列出允许修改的既有文件和计划新增文件。小范围必要辅助修改先记录理由及受影响测试；跨领域或改变外部合同的扩展先更新任务规格，再实施。保留用户已有修改及 _build/、paseo.json。

当前 docs/*、多数新增 tests 文件和根规划文件受 .gitignore 影响。T00 只精准放行本执行包、3.0 方案、合同与测试夹具；运行报告、原始私有输入仍保持忽略。Git 跟踪规则变化不等于授权暂存、提交或发布。

单次任务失败用新的局部修改恢复一致状态，使用 legacy 配置回退运行路径，保留证据。禁止用 git reset --hard 或整目录恢复清除用户改动。未授权的提交、推送、标签、Release、安装副本更新及其他项目同步都不属于默认执行动作。

## 4. 每项任务的完成条件

任务状态：pending → in_progress → implemented → done；阻塞使用 blocked。implemented 表示实现及作者验证完成，done 还需已记录审查结论且无未解决高优先级问题。无法获得独立审查时保留 implemented，交接说明；不能伪造 done。blocked 不算完成。

每个任务在 evidence/Txx.md 记录：

1. 输入基线 HEAD、开始及结束时间、实际改动文件。
2. 红灯命令及预期失败原因，绿灯命令、退出码及日志路径。
3. 真实转换输入/模板摘要、模型/输出报告和相关断言。
4. 审查结果、残留问题、下一任务可执行条件。
5. 是否存在实际行为变化，旧路径是否仍通过。

详细运行日志放 wx_output/modular-v3/，evidence 只保存摘要和路径。状态清单包含 evidence、review、blocker、next_action；根 task_plan.md 仅保留执行入口指针，不能出现另一份相互冲突的逐任务状态。

对于纯兼容重构，旧黄金结果必须一致。新能力的目标断言与旧基线分开；不能重写旧期望来掩盖回归。既有失败只能在 T00 锁定精确用例和原因后单列，新增失败阻止完成。

## 5. 恢复与漂移

恢复时先读 status.json 和最近任务证据，再核对 git diff 与实际测试。某任务 marked done 但文件或测试证据不符时，重开该任务并记录原因。上次 in_progress 不从零重写，先核验已完成步骤。

方案或合同摘要改变时做影响分析，失效相关任务及下游验收，不自动清空全部进度。代码 HEAD 在执行过程中改变属正常，使用每项 evidence 的基线关联，不能要求始终等于编制时 HEAD。

源码编译失败、真实输入丢失、语义归属无法确定或必需平台不可用时记录具体 blocker。测试中人工构造故障用于验证降级，不能把真实环境故障当作预期测试通过。
