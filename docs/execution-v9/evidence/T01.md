# T01 附录容器按 AST 位置落位

## 红灯

基线：`dev` 分支 `5530ca5`（版本 0.14.4），全量 `1349 passed`。

用最终用例在未改实现（HEAD 的 `scripts/`）上实测：

```
scripts/.venv/bin/python3 -m pytest tests/test_modular_appendix_placement.py -q
6 failed, 1 passed
```

与本工单直接相关的失败项：

- `test_the_appendix_container_follows_every_block_that_precedes_it`：容器不是 root 的最后一个子节点，附录之前的块被留在容器之后。
- `test_the_container_position_does_not_drift_with_extra_ast_nodes`：带图与不带图两种样例的容器之后都残留正文块，且不一致。
- `test_the_reported_document_keeps_its_pre_appendix_paragraphs`：真实文档里 `此模板还设置了页码…` 出现在附录之后。

通过的那一项是 `test_the_conversion_reports_clean_audits`，属审计守卫，改动前后都应通过（不是红灯转绿）。

两处测量口径更正（独立审查发现）：

1. 夹具第一版用 `Document()` 建源文档，缺少 `附录标题` 等样式（`KeyError: no style with name '附录标题'`），当时测到「6 failed」属夹具失败，不作为红灯依据；改为从模板建文档并清空正文后重测。
2. 容器用例第一版只断言两个正文块位于容器之前，而夹具把图片放在这两段之间，未改实现下留在容器之后的只是末尾空段，因此该用例当时是**通过**的，缺陷实际由 `test_the_container_position_does_not_drift_with_extra_ast_nodes` 捕获。复审据此补上「容器必须是 root 最后一个子节点」的断言，该用例才成为红灯。

- 新增 `range_index`：范围内首个映射后节点在 `document["children"]["root"]` 中的位置，取不到时回落到子节点数（追加到末尾）；

## 实测

**报告**：`status=completed_with_warnings`（唯一提示为既有的 `source_heading_level_normalized`）、`model_audit`、`saved_output_audit`、`appendix_preservation_audit` 均通过，`unexpected_styles=[]`，`risk_warnings` 为空。

**落位机制复核**：插桩 transaction 显示创建申请索引由 127 变为 130（AST root 中附录标题的实际位置），容器不再前插。

## 未关闭

- 既有门禁仍看不到这类顺序缺陷：`saved_output_audit.paragraph_order_changed` 比较的两侧都来自同一份 AST，`audit_native_appendix` 只校验集合归属。本工单只修落位，未新增门禁。是否要为「AST 顺序与源顺序一致」加一道结构审计，留待裁定。
- 既有归属缺口（独立审查发现，非本包引入）：范围**内部**的内联图片所物化的 `*-image` 节点不在 `root_node_ids` 里（该列表来自 SourceFacts 的 root 子节点），因此不会被移进容器，会作为孤儿留在容器之后。本包未修，记为残留。

## 独立审查与复审

审查由另一独立智能体执行（`git diff`、全量测试、并在 `$COMMANDCODE_SCRATCHPAD` 用运行期回退实现的方式复现红灯与反例）。结论：无阻断项，可落地。逐条处置：

- **F1（证据口径，已修）**：证据原写「6 failed」来自缺少附录样式的初版夹具，且容器用例在最终夹具下未改实现时实际通过。已按实测改写为「6 failed, 1 passed」，并记录两处口径更正；同时按审查建议给容器用例补上「容器必须是 root 最后一个子节点」的断言，使其成为真正的红灯。
- **F2（覆盖缺口，已修）**：不变量 2、4、5、6 原先只有部分断言。已补：容器用例断言附录之前各块的角色（heading / body）与容器归属；标题用例断言附录四级样式各自的直接级别；新增 `test_the_conversion_reports_clean_audits` 断言三项审计、`unexpected_styles` 与风险提示。
- **F3（既有归属缺口，记为残留）**：范围内部图片的物化节点不会被移入容器。非本包引入（标题始终是 `root_node_ids[0]`，与容器索引无关），且 `audit_native_appendix` 看不到。已在「未关闭」记录。
- **F4（键名复用，已记录）**：`outline_level` 在 `presentation.outline`（选择样式）与 `presentation.paragraphs`（写直接属性）里含义不同。两者由不同路径消费且无块同时持有，已在 `normalization._paragraph_presentation` 的 docstring 说明。
- **F5（表格归属，已修）**：附录标题的呈现记录原先绕过表格归属抑制。已加 `table_owned` 判断，与图片/正文记录一致。
- 审查同时确认：`_apply_paragraph_outline_level` 的 CT_PPr 元素顺序正确（`w:outlineLvl` 位于 `w:jc` 与 `w:rPr` 之间）、重复调用不产生重复元素、`bool` 与非 `int` 记录被忽略；`range_index` 在双附录、范围为首个子节点、范围前有表格、范围前有列表、范围内有列表等形状下都正确；`start_order` 仍只作来源追溯。

复审：F1、F2、F5 修完后重跑专项 `7 passed` 与全量 `1356 passed`，真实文档与模板自转换的实测结论不变。
