# T01 附录容器按 AST 位置落位

依赖：无。

## 背景

见 `README.md` 问题一。附录容器的 `create_node` 索引用的是 SourceFacts 的 root 位置，而该索引的语义是 AST root 的子节点位置；两份列表长度不同（AST 会为内联图片物化额外节点），于是容器落位偏前，附录之前的块被挤到文末。

## 工作项

`scripts/wxdf/semantics/appendices.py::collect_native_appendix_candidates`：

- 创建索引改为「范围内首个映射后节点在 `document["children"]["root_id]` 中的索引」；首个节点不在 root 中时回落到 `len(root children)`；
- `source_range.start_order` 继续写 SourceFacts 位置，语义不变；
- 不新增字段、不改 `index` 的语义、不改事务。

## 红灯先行

先写 `tests/test_modular_appendix_placement.py` 的 T01 用例，在未改实现的工作树上确认失败，再实现。预期初始失败：带内联图片的样例中附录容器位置偏前、三个正文块落在容器之后。

## 验收

- 不变量 1、2、5（见 `README.md`）逐条有测试钉住。
- 端到端：合成样例与真实文档 `技术文件格式及书写要求.docx` 转换后，附录之前的段落顺序与源顺序一致。
- 回归：全量测试通过，通过数不低于本包开始时的 1349；既有附录审计、保存后审计与模型审计保持通过。

## 证据

写入 `docs/execution-v9/evidence/T01.md`：红灯/绿灯计数、落位前后的 root 尾部实测、真实文档顺序核对、独立审查结论与残留。
