# T02 附录标题的直接大纲级别

依赖：无。

## 背景

见 `README.md` 问题二。输出的目录域来自模板（`TOC \o "1-3" \h \u`），按大纲级别生成条目；模板的 `附录标题` 样式 outlineLvl 为 1，Word 重算后把附录标题排到目录第 2 级，而模板与源文档的目录缓存都把它放在第 1 级。用户裁定 A：给附录标题写直接大纲级别 0。

## 工作项

### 1. 呈现记录

`scripts/wxdf/normalization.py`：`appendix_role == "title"` 的块在 `presentation.paragraphs` 中记录 `outline_level = 0`。附录一级至三级标题不记录（继续由样式提供大纲级别）。

### 2. 写出直接级别

`scripts/wxdf/rendering.py`：按呈现记录写出 `w:pPr/w:outlineLvl`，元素置于 `w:rPr` 之前（CT_PPr 顺序）；同名字段先删后写，避免重复。

### 3. 治理文档

`AGENTS.md` 决策 7 增补：附录标题在交付文档中带直接大纲级别 0（目录第 1 级），附录一至三级标题沿用样式的大纲级别；legacy 的 `\t` 映射与 `toc_contract.TOC_CUSTOM_STYLE_LEVELS` 仍只服务诊断链路。

## 红灯先行

先写 `tests/test_modular_appendix_placement.py` 的 T02 用例，在未改实现的工作树上确认失败，再实现。预期初始失败：附录标题段落没有直接 `w:outlineLvl`。

## 验收

- 不变量 3、4（见 `README.md`）逐条有测试钉住。
- 端到端：真实文档转换后附录标题带直接级别 0，附录一级标题不带直接级别。
- 回归：全量测试通过；三项审计 `passed`，`unexpected_styles` 为空。
- 人工确认（外部门禁）：用户在 Word/WPS 中打开输出，目录里附录大标题应位于第 1 级。

写入 `docs/execution-v9/evidence/T02.md`：红灯/绿灯计数、输出 XML 实测、真实文档实测、独立审查结论与残留。
