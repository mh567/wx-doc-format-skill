# T01 冻结 spec 与失败样例库

## 分工

Codex 定 spec 字段级定义与样例矩阵;Claude 实施落地;Codex 审查及复审。

## 范围

- `docs/execution-v6/README.md`
- `docs/execution-v6/status.json`
- 失败样例库(独立可重跑的输入/期望输出夹具,覆盖 Word/WPS/Markdown 与当前真实问题文档)
- 对应测试与 `evidence/T01.md`

## 依赖

无。可立即启动。

## 工作

1. 补齐 `docs/execution-v6/README.md` 的字段级定义:证据字段清单(`source_ilvl / effective_ilvl / semantic_level / render_level / start_value / sequence / restart_scope / num_id / abstract_num_id / num_fmt / lvl_text / w:ind / suffix / p_style_ref`)、候选状态枚举(`OUTSIDE_LIST / LIST_ITEM / ITEM_CONTINUATION / ITEM_CHILD_BLOCK / NESTED_LIST_ITEM / LIST_END / AMBIGUOUS`)、全局约束列表、不变量清单。
2. 建立失败样例库,每类至少一个可重跑样例并附「当前行为 vs 期望行为」:
   - 标题误识为列表项
   - 连续正文段误识为列表
   - 有序/无序类别选错
   - 一级与二级优先级选错
   - 多层有序嵌套、多层无序嵌套、有序无序交叉嵌套、列表穿插正文嵌套
   - 子列表新 numId 但 ilvl=0
   - 列表项含续接正文
   - 编号缺失/损坏
3. 为样例库写回归断言,确认当前实现失败。
4. 预留后续工单所需 fixture 命名约定。

## 验收

- spec 字段级定义齐备,无待定项。
- 失败样例库可重跑,且当前实现稳定失败(红灯)。
- 真实样例来自仓库既有问题文档或构造的等效 fixture。
- 全量测试暂未引入新失败(仅新增红灯用例)。

## 红灯

新增一个测试文件,断言上述样例库在转换后满足期望列表语义;初始运行应失败。
