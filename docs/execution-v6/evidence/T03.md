## 工作项落地

1. **候选状态编码**：`_build_state_candidates(facts)` 只消费 `SourceFacts`，不再读取已裁决的 `result["items"]`。`_state_candidates_for_paragraph` 按原始证据为每块发出带评分的候选状态，并在证据确实分裂时发出真实竞争项：疑似标记块同时发 `LIST_ITEM` 与较低分的 `OUTSIDE_LIST`，受保护标题发 `OUTSIDE_LIST`（0.95）与低分 `LIST_ITEM`（0.2），并携带 `protected_content / structure` 负向证据，合同降级块携带 `contract` 负向证据，低置信度标记块（`numbering_status="ambiguous"`）只发 `OUTSIDE_LIST`。`LIST_STATE_ENUM` 由 `_validate_state_enum` 校验。`items / lists / continuations` 由裁决结果物化，不再先于裁决产生。
2. **Resolver 复用**：`_arbitrate_state_candidates` 把状态候选投影到既有 `CandidateSet` 合同并调用 `wxdf.resolver.resolve`，每块唯一归属、证据强度优先级、同分同强度冲突进 `unresolved` 由既有 Resolver 承担。同强度平局产生 `ambiguous_list_state` 诊断并把 `status` 置为 `unresolved`，普通模式不静默接受歧义结构；低置信度但解析器已裁决为正文的块不进该路径（见工作项 5）。平局当前只能由合成证据触发，真实输入的可达性见残留 10。
3. **单级列表端到端**：列表树物化沿用 `source_ast.materialize_list_semantics`；`semantic_level -> render_level` 投影沿用 `normalization`；渲染器写出直接 `w:numPr`（复用 `numbering_ids` 的 `w:numId`，`w:ilvl` 按 render level）。有序列表不再依赖样式里被钉死为 0 的层级。
4. **保存回读比对**：`audit_list_readback` 重新解析保存后的 DOCX，逐段读取 `w:numId` 与 `w:ilvl`，与语义列表比对；不一致产出 `list_readback_mismatch`，该问题并入 `saved_output_audit` 并阻断发布。
5. **低置信度不进歧义**（第四轮 FIX 1）：解析器 `numbering_status="ambiguous"`（`isolated_generic_numbering`）的块保持正文（裁决 `OUTSIDE_LIST`），并产出 `low_confidence_list_marker`（info）降级记录进 `list_semantics.downgrades`；不发 `ambiguous_list_state`、不设置 `unresolved`。红灯先行：修改前 `test_t03_ambiguous_numbering_reaches_published_report` 失败（单个编号段与 `[编号][正文][编号]` 均被判 `completed_with_warnings`）。护栏：`test_t03_ambiguous_numbering_reaches_published_report`（单个编号段 + `[编号][正文][编号]`）、`test_t03_real_conversion_surfaces_readback_and_render_clamp`（`input/test_baseline.md`、`input/benchmark_report.md` 保持 `completed` 且 `risk_warnings` 为空）。普通文档回归并入既有测试，未新增测试函数。
6. **约束去重**（第四轮 FIX 2）：`_validate_state_constraints` 对同一节点的跳级只产出一次约束 4，不再同时产出约束 3 的「无父项」发现，`list_constraint_violation` 不再因同一缺陷重复两次；`tests/test_modular_lists.py` 相应收紧为断言 `[(4, "u2")]`。

| 6 标题与附录边界按策略结束 | 受保护结构作为 `OUTSIDE_LIST` 的负向证据进入裁决 |
| 7 低置信度进歧义报告 | 解析器的 `numbering_status="ambiguous"`（`isolated_generic_numbering`）表示证据不足且解析器已裁决为正文：该块保持正文（`OUTSIDE_LIST`），并以 `low_confidence_list_marker`（info）记录进 `list_semantics.downgrades`，不设置 `unresolved`、不发 `ambiguous_list_state`。`ambiguous_list_state` 与 `status="unresolved"` 只保留给 Resolver 平局（同块两个候选同分同强度，`resolve()` 返回 `candidate_conflict`），由 `test_t03_genuine_equal_strength_tie_is_unresolved` 覆盖。该平局当前仅由合成证据触发，尚无真实适配器输入（见残留 10） |
| 8 同 sequence 续接 | 未实现。候选状态不携带序列身份，序列续接仍由 `_list_family` 与既有分组承担，归属 T06 |
| 9 类别切换重启 | 部分实现。显式列表容器的候选状态携带 `list_kind`，隐式列表段的类别仍由 `_list_family` 在分组阶段判定；完整策略归属 T06 |
| 10 `restart_scope` 边界 | 未实现，`lvl_restart` 已入目录待 T06 消费 |

补充：`_state_candidate` 的 `score` 字段参与裁决。`_arbitrate_state_candidates` 在调用 `resolve()` 前按每块读取 `score`，只把该块最高分的候选送入 Resolver，低于本块最高分的竞争候选被预过滤掉；进入 Resolver 的存活候选仍由 `resolver._candidate_strength` 按 `positive_evidence.kind` 排序，同分且同强度时才产生 `candidate_conflict`。因此评分的作用是「每块先取最高分候选」的预过滤，不是阈值判定。

## 独立复审发现与修复

首轮双轴审查判定工单核心机制只是名义成立，四项主要问题在本轮修复：

1. **候选状态派生自已裁决结果**（主要）。原 `_build_state_candidates(facts, result)` 读取 `result["items"]` 与 `result["continuations"]`，每块只发一个状态，`state_unresolved` 恒空，`AMBIGUOUS` 与 `LIST_STATE_ENUM` 不可达，`state_decisions` 无人消费。现已改为只消费 `SourceFacts`、按原始证据发出真实竞争候选，并由裁决结果物化 `items / lists / continuations`；`LIST_STATE_ENUM` 由 `_validate_state_enum` 校验。护栏：`test_t03_state_candidates_encode_competing_states_from_raw_evidence`、`test_t03_genuine_equal_strength_tie_is_unresolved`。
2. **全局约束 3/4 无人执行**（主要）。`resolve()` 看不到顺序、层级与父项，原先只做证据强度裁决。现由 `_validate_state_constraints` 显式承担 README 约束 3（深层须有父项）与约束 4（逐级递增），违反产出 `list_constraint_violation`。护栏：`test_t03_deep_item_without_parent_reports_constraint_3`、`test_t03_level_jump_reports_constraint_4`。
3. **渲染器静默夹层**（主要）。层级未被目标编号实例定义时原先直接夹回 0 且无记录，会掩盖缺失能力。现发出 `list_render_level_clamped` 诊断。护栏：`test_t03_ordered_level_clamp_is_reported_not_hidden`。
4. **回读审计无法发现编号回归**（主要）。原实现只按段落样式名重建成员与层级，不读 `w:numId` 与 `w:ilvl`；复审实测把全部项改成 `ilvl=77 numId=999`、甚至删除全部直接 `numPr` 仍然通过。现读取保存文件的 `w:numPr/w:numId` 与 `w:numPr/w:ilvl` 逐段比对，问题并入 `saved_output_audit` 并纳入发布门禁。护栏：`test_t03_readback_detects_tampered_ilvl`、`test_t03_readback_detects_tampered_num_id`、`test_t03_readback_detects_removed_num_pr`、`test_t03_readback_failure_is_a_visible_audit_finding`。

次要项已修复：`list_state` 加入 `SAFE_PROPERTY_SCOPES`；移除恒真断言与占位断言；重命名与断言内容不符的测试；`list-semantics` 证据计数改为可辨识的取值。

## 已知残留（交给后续工单）

1. **pStyle 层级继承尚未端到端生效**（承 T02 残留 1）。正文段落的 `numbering_status / num_fmt / lvl_text` 仍来自 `list_detector.analyze_docx_lists` 的分组裁决，原生目录算出的 `effective_ilvl` 只进入证据与候选状态，尚未驱动「是否识别为列表」的分组。归属 T04/T10。
2. **产品路径的非零多级输出受限**。`wx-default-v2` 在 `scripts/wxdf/normalization.py` 的 `normalize` 中把有序项的 `target_level` 钉为 0（`target_level = 0 if strategy == "wx-default-v2" and list_kind == "ordered" else depth`），于是每个有序项的角色都由 `_style_role("ordered", 0)` 解析为 `list_letter`（`numId=3`），`list_decimal`（`numId=8`）在这条路径上从未被使用；真实两层有序列表仍写出全零 `w:ilvl`。模板本身已提供多级编号实例（`numId` 1/2/7/19 各定义 9 级），缺的是策略让有序项产出非零 `render_level` 并绑定到多级实例，归属 T04 与 T08。
3. **`num_id` 双源**（承 T02 残留 2）：证据同时从目录顶层与 `numbering_definition_ref` 写入。归属 T10。
4. **`lvlRestart` 未消费**（承 T02 残留 3）：README 全局约束 10 的重置行为待实现。归属 T06。
5. **`LIST_END` 状态已枚举未发出**：边界终止当前由受保护块与 `OUTSIDE_LIST` 表达。标题/正文边界与显式终止归属 T07，编号边界归属 T06。
6. **回读比对粒度**：`audit_list_readback` 已比对扁平 `(list_kind, numId, ilvl)` 读取序列，尚未比对父链、列表树形状与每级序号值。归属 T04/T09。
7. **候选评分只做预过滤**：`_arbitrate_state_candidates` 读取 `score`，在调用 Resolver 前按每块最高分预过滤竞争候选；进入 Resolver 的存活候选仍由 `_candidate_strength` 按 `positive_evidence.kind` 排序。评分不承担阈值判定；如后续要引入阈值化的证据评分，归属 T04。
8. **渲染夹层诊断的非阻断口径**：`list_render_level_clamped` 记录在 `render_result` 并经模块证据暴露，不单独阻断发布；真正的多层输出能力归属 T08。
10. **歧义报告对真实输入不可达**：`list_item` 平局要求 `marker_kind` 存在且 `numbering_status` 不属于 `detected/ignored`，而两个适配器只在 `detected` 时写 `marker_kind`，因此真实文档的 `state_unresolved` 恒为空，`ambiguous_list_state` 不会出现。README 约束 7 的字面阈值语义因此尚未落地。真实触发条件依赖嵌套产生的竞争父项候选，归属 T04/T05。
9. **显式列表容器的候选状态参与度**：隐式列表段按裁决物化，显式列表容器在裁决只允许 `LIST_ITEM` 时也通过 `decided_states` 过滤，但容器自身的存在仍先于裁决。归属 T04/T10。
10. **隐式列表段的尾部续接未实现**（README 约束 5 的缺口）：`ITEM_CONTINUATION` 与 `ITEM_CHILD_BLOCK` 只在显式 `list_item` 容器内发出；隐式 DOCX 段被 `_implicit_list_runs_for_parent` 在首个非列表块处切断，`[列表项][正文][列表项]` 因此物化为两个列表段。归属 T05。
11. **显式列表容器未做 README 约束 3/4 校验**：`_implicit_list_runs_for_parent` 对 `list`/`list_item` 父项返回 `[]`，约束 3（深层须有父项）与约束 4（逐级递增）只覆盖隐式列表段，显式容器内的违规不会被这两条校验发现。归属 T04/T05。

## 独立复审结论

首轮复审：判定核心机制名义成立，四项主要问题为候选集派生自已裁决结果、约束 3/4 无执行者、渲染静默夹层、回读审计无法发现编号回归。

第二轮复审：确认 R3b、R5 与次要项已真正修复；R1 与 R1b 在机制层已修复并有会失败的护栏测试，但指出三项仍不成立：约束违规只进内部列表不进 `diagnostics`（`list_constraint_violation` 不出现在报告中）、约束 7 的歧义路径对真实输入不可达、以及验收表把「不再写零」说成已达成且把原因错误归给模板缺少多级定义（模板实际包含多级实例）。

第三轮修复：约束违规已并入 `diagnostics`（`test_t03_level_jump_constraint_reaches_published_report`、`test_t03_constraint_validation_agrees_with_materialized_flattening`）；歧义路径已由解析器的 `numbering_status="ambiguous"` 证据映射为 `AMBIGUOUS` 候选并端到端验证（`test_t03_ambiguous_numbering_reaches_published_report`）；`check_saved_output` 先认直接 `w:numPr`（`test_t03_saved_output_honours_direct_numbering`）；`w:numPr` 按 CT_PPr 顺序插入（`test_t03_direct_numbering_is_inserted_in_pPr_order`）；回读问题合并后重算 `audit_findings`（`test_t03_readback_findings_are_merged_into_saved_output_findings`）；验收表与残留已按事实改写（见上），非零多级输出的真实归属改为 T04 与 T08。

第四轮修复（本轮实施）：FIX 1 按 README 不变量 7 重标定低置信度门控：解析器已裁决为正文的低置信度块保持正文（`OUTSIDE_LIST`）并记录 `low_confidence_list_marker`（info），`ambiguous_list_state` 与 `status="unresolved"` 只保留给同强度平局，L09 恢复 `completed`；FIX 2 同一跳级缺陷只报一次约束 4；FIX 3 删除死代码 `lists._reading_order` 并改写约束表第 2 行；FIX 4 修正候选评分、约束表第 2/3/4/5/7 行、验收表第 2 行、真实转换表单级行与模板因果表述。护栏：`test_t03_ambiguous_numbering_reaches_published_report`（单个编号段 + `[编号][正文][编号]`）、`test_t03_real_conversion_surfaces_readback_and_render_clamp`（两份真实 Markdown）、`test_t03_genuine_equal_strength_tie_is_unresolved`、`test_l09_merged_and_nested_table_cells_are_unique_and_scope_local`、`tests/test_modular_lists.py::test_implicit_docx_depth_jump_is_unresolved_and_container_scope_isolated`。
