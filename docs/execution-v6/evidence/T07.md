## 工作项落地

### 工作项 1：标题与连续正文段不再进入列表，归入歧义时上报

- **标题结构优先于已确认编号**（`lists.py._is_protected`）。改动前 `numbering_status == "detected"` 的短路在标题样式与手写章节编号判定之前返回，导致「带编号定义的标题」被当作列表项。改动后标题结构（role / 标题样式 / 手写章节编号文本）先于短路判定，`numbering_status == "detected"` 只对非标题内容生效。
- **手写章节编号样式**。`_is_protected` 的样式判定从 `"附录标题" in style` 放宽为 `"标题" in style`，使 `章标题` / `节标题` 这类中文章节编号样式被识别为标题结构（`附录标题` 被该规则包含）。手写 `6.3`（两段）与 `第X章` 文本继续由 `protected_text_reason` 的 `_MANUAL_HEADING_RE` 保护。
- **真实可达的歧义平局**。改动前 `_state_candidates_for_paragraph` 对受保护标题只发 `OUTSIDE_LIST`（structural）与 `LIST_ITEM`（heuristic），`OUTSIDE_LIST` 直接胜出，标题从不进入歧义报告。改动后当标题结构同时携带**已确认编号实例**（`numbering_status == "detected"`、有 `marker_kind`、无手写 `visible_marker`）时，同一块发两个**同强度 structural** 候选：`OUTSIDE_LIST`（`protected_heading`）与 `LIST_ITEM`（`source_facts_list_item`）。`resolver.resolve` 判定为 `candidate_conflict` 并写入 `unresolved`，块不产生任何状态决策，因此不会物化为列表项；歧义进入 `ambiguous_list_state` 诊断。这是工作项 2 的最强形式。
- **连续正文段**。无 marker 的正文段继续保持 `OUTSIDE_LIST`；带 marker 但无编号确认的正文段由证据与上下文裁决（候选 + Resolver），本条沿用 T03/T05 已落地的候选机制，本工单未改该路径。

### 工作项 2：普通模式不静默接受歧义结构，带诊断地降级

- 「标题 + 已确认编号」的同强度平局使 `state_unresolved` 非空，`analyze_lists` 追加 `ambiguous_list_state`（info）诊断并把 `list_semantics.status` 置为 `unresolved`（`README` 不变量 7：存在未解决候选时 `status != "completed"`）。块保持正文，不静默提升。
- 受保护的列表式正文段（`marker_kind` 且受保护）另发 `protected_list_like_text` 诊断，工作项 3 的每类混淆内容都带自身 reason（`ip_address` / `legal_clause` / `api_path` / `formula`）。
- 真实可达性：本工单使「标题 + 已确认编号」的同强度平局**从真实 DOCX 输入可达**，见下方 `test_t07_chapter_heading_style_end_to_end` 与 `test_t07_chapter_heading_style_conversion_report`（自定义 `章标题` 样式 + `w:numPr`，解析器给出 `numbering_status="detected"`，标题样式不在 legacy 受保护集合内）。这是 T03/T04/T05/T06 残留中「歧义报告仅由合成证据可达」的部分收口：标题样式与编号定义冲突的形态现在由真实解析路径触达。
- 未落地：README 约束 7 的**字面分数阈值语义**不在本工单，阈值数值化与 LLM 门控仍归 T09。low-confidence 编号继续保持正文并只记 info 降级（T06 口径），未改动。FIX 轮判定「标题 + 已确认编号」属约束 6 可裁决，撤掉了它作为歧义来源的做法。
- `LIST_END`：本工单未发出 `LIST_END` 候选。终止继续由受保护块与 `OUTSIDE_LIST` 表达，理由与 T06 一致（对已裁决为 `OUTSIDE_LIST` 的边界块再发 `LIST_END` 会形成同强度平局）。

### 工作项 3：受保护名单扩展

单一所有者：`scripts/wxdf/semantics/protected.py` 的 `protected_text_reason`（`lists.py` 只是消费方，`protected.py` 内不再新增并行的重复判定）。扩展内容：

| 内容类别 | 规则 | reason |
| --- | --- | --- |
| IP 地址 | `_IPV4_RE` + `_is_ipv4`（逐段 0-255 且至少一段大于 9，可选端口）。避免把 `1.2.3.4` / `4.2.1.3` 这类多级编号误判为地址 | `ip_address` |
| API 路径 | `_API_PATH_RE`（`/...`、`http(s)://...`、`ws(s)://...`）。与既有 `_API_RE`（`API:` / `接口`）和 `_HTTP_API_RE`（`GET /...`）互补 | `api_path` |
| 法规条款 | `_LEGAL_CLAUSE_RE`（`第<任意数字>条`、`第<阿拉伯数字>款/项`、`本条/款/项`；`第一项`/`第二项` 这类中文数字列项被有意排除，避免与正文列项相撞） | `legal_clause` |
| 公式 | `_looks_like_formula`（LaTeX 命令，或数学符号，或等式文本）。CJK 守卫只作用于等式分支：符号分支不排除中文，因此 `面积 = 长 × 宽` 也判为 `formula` | `formula` |
| 版本号 / 日期 | 沿用既有 `_VERSION_RE` / `_VERSION_CONTEXT_RE` / `_DATE_RE`，未改动 | `date_or_version` |

IP / API 路径 / 法规条款的检查放在 `visible_marker` 分支之前，因此真实 DOCX 里被标记扫描器读成 decimal-chain 的 IP 段（无 `w:numPr`，只有 `visible_marker`）能被正确保护；公式检查放在无 `visible_marker` 的尾部路径，避免把带手写 marker 的真实列表项文本误判为公式。受保护内容的匹配与既有 `protected_text_reason` 同源，未新增第二处策略。
