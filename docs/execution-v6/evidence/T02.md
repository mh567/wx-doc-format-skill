## 编号目录覆盖

`build_numbering_catalog` 逐件读入 OOXML 编号定义：

| OOXML 项 | 读取位置 | 落地字段 |
| --- | --- | --- |
| `w:lvl/@w:ilvl` | `w:abstractNum/w:lvl` | `abstract_levels[abstract][ilvl]` |
| `w:start` | `w:lvl/w:start/@w:val` | `start` → `start_value` |
| `w:numFmt` / `w:lvlText` | `w:lvl` 子元素 | `num_fmt` / `lvl_text` |
| `w:pStyle` | `w:lvl/w:pStyle/@w:val` | `abstract_pstyle[abstract][styleId]` → `effective_ilvl` |
| `w:suff` | `w:lvl/w:suff/@w:val` | `suffix` |
| `w:lvlRestart` | `w:lvl/w:lvlRestart/@w:val` | `lvl_restart` |
| 编号级 `w:ind` | `w:lvl/w:pPr/w:ind/@w:left` | `w_ind` |
| `w:lvlOverride` | `w:num/w:lvlOverride` | `num_level_overrides[num][ilvl]` |
| `w:startOverride` | `w:num/w:lvlOverride/w:startOverride/@w:val` | `start_override` |
| `w:abstractNumId` | `w:num/w:abstractNumId/@w:val` | `num_to_abstract` |
| 缺失 / 损坏定义 | `num_to_abstract` 指向不存在的 `abstractNumId`，或 `abstractNumId` 缺失 | `status=ignored` + `invalid_numbering_definition`，`analyze_lists` 产出 `missing_numbering_definition` / `invalid_numbering_definition` 诊断与 `downgrades` 记录 |

段落样式 `numPr` 的 `ilvl` 按 MS NumberingProperties 规则忽略：`_resolve_effective_ilvl` 用样式 id 或样式名到
`w:lvl/w:pStyle` 的关联确定实际层级，`source_ilvl` 仍保留源声明值。

## 语义模型扩展

- 每个列表项输出 `source_ilvl / effective_ilvl / semantic_level / render_level`，四者分开保存。
- 隐式列表组输出 `restart_expression`：`start_value / sequence / restart_scope / num_id / abstract_num_id`，
  取代原先的布尔 `restart`。显式列表容器（Markdown）沿用容器自身的 `source_start` / `source_sequence_id`。
- `sequence` 复用既有稳定拼写 `docx-sequence-<num_id>-<abstract_num_id>`，与
  `semantics.lists.json_sequence_id` 一致，未引入第二套序列身份。
- `source_ast.materialize_list_semantics` 的列表项节点新增 `content_blocks` / `child_lists`，
  `(ast, candidates, item_map)` 三元返回与 `list_item_map` 接缝未变，附录复用无回归。

## 独立审查发现与修复

首轮双轴审查（Standards + Spec）发现 3 项主要问题，均已修复：

1. **编号级 `w:ind` 读错嵌套层**（主要）。`_level_ind_values` 原先把 `w:ind` 当作 `w:lvl` 直接子元素读取，
   真实 Word/WPS 定义位于 `w:lvl/w:pPr/w:ind`，导致真实文档 `w_ind` 恒为 `None`；原测试构造的是不合规 XML。
   已改为读 `w:lvl/w:pPr/w:ind`，测试夹具同步改为合规形状。
2. **`lvlRestart` 读错**（主要）。`_level_values` 原先以属性方式读取 `w:lvlRestart`，恒为空。
   已改为读取 `w:lvl/w:lvlRestart/@w:val`；`w:start` 同样从属性改为子元素。
3. **序列相等性切断手工标记列表**（主要回归）。`lists.py` 曾以 `sequence` 相等作为分组条件，
   手工标记段落没有编号实例时序列退化为逐段唯一 id，连续 `a) b) c)` 被拆成 3 个列表；
   与 HEAD 相比属于未声明的行为变化。已恢复为 `list_kind` + `parent_item_id` 分组，
   编号实例的合并与拆分留给 T06。新增回归断言 `test_t02_consecutive_visible_markers_stay_in_one_list`。

次要项已修复：`SAFE_PROPERTY_SCOPES` 中 22 个未被任何决策使用的投影项已移除（该表是决策
`property_scope` 白名单，不是证据字段登记处）；未被任何 module 提供的 `native_numbering_catalog`
能力合同已移除；`num_start_overrides`、`w:tabs` / `_level_tab_values` 等死字段已移除；
`describe_docx_paragraph` 中重复的 `_resolve_effective_ilvl` 调用已合并；文档串名已更正。

## 复审结论

复审智能体确认：RISK 1（编号级 `w:ind` 嵌套）与 RISK 6（手工标记列表被拆分）均已修复并有复现反例；
`SAFE_PROPERTY_SCOPES`、`native_numbering_catalog`、`num_start_overrides`、`w:tabs`、文档串、
