### F1（BLOCKER）回读语义重建在生产中从不运行

`scripts/wxdf/kernel.py` 把输出暂存为 `.{output}.native-v2.staging`，`native_stages` 审计该暂存路径。`auditing._rebuild_readback_lists` 调用 `parse(Path(path))`，按文件后缀分派，`.staging` 后缀落入 Markdown 分支，把 DOCX zip 当 UTF-8 读，稳定复现 `UnicodeDecodeError`；异常被捕获，只报非阻断的 `list_readback_rebuild_skipped`。于是每次真实转换 `semantic_rebuild_checked=false`，四个语义不变量 `deep_items_have_parent` / `continuations_have_owner` / `low_confidence_has_diagnostics` / `no_silent_ambiguity` 全为 `null`，却仍报 `passed=true`；README 不变量 2 与 3 在生产中未被强制，T09 的验收声明因此不成立。

修复：

- `scripts/wxdf/parsers.py`：`parse` 接受可选的 `source_type` 容器提示（`docx` / `markdown`），无法从后缀判定时由调用方直接给出容器类型。
- `scripts/wxdf/auditing.py`：`_rebuild_readback_lists` 以 `{"source_store": None, "source_type": "docx"}` 调用 `parse`，暂存名的后缀不再决定容器类型。

守卫测试（`tests/test_t09_readback_audit.py`，两项新增）：

- `test_t09_readback_semantic_rebuild_runs_in_production`：真实 `ConversionKernel` 转换两级嵌套 Markdown，读报告的 `native_module_evidence["native-auditor"]["downstream"]["list_readback"]`，断言 `semantic_rebuild_checked is True` 且四个语义不变量为 `True`（非 `null`）。

### F2（MAJOR）稳定报告字段在无合同说明下被移除

- 生产者已随 `list_detector` 删除，消费方若继续读该键就落在 F3 的「读一个无人生产的合同」。

消费方更新：`review_loop.collect_audit_findings` 改读列表回读的继任记录（`native_module_evidence["native-auditor"]["downstream"]["list_readback"]` 的 `issues`），把它作为非可修复的语义发现上报，从而不再依赖死键。守卫测试 `tests/test_review_loop.py::test_list_readback_findings_come_from_the_native_evidence`。`tests/test_review_loop.py` 的 `_report()` 夹具去掉 `list_preservation_audit`，相关计数随之更新。
