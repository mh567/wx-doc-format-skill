## 工作项落地

1. **深层须有前置父项、逐级递增、类别与层级独立**（工作项 1）。`_validate_state_constraints` 继续对隐式列表段承担 README 约束 3 与 4。类别与层级的独立性体现在候选状态只按 `marker_kind`/`num_fmt` 定 `list_kind`，层级由结构（`explicit_depth`、`effective_ilvl`、嵌套裁决）决定，二者在 `_emit_group` 中分开写入 `list_kind` 与 `semantic_level`。
2. **`numId+ilvl=0` 子表识别为子级**（工作项 2，冻结红灯）。`_resolve_sublist` 的裁决：声明层级为 0 且 `numId`（实例身份）不同于当前开放的一级列表时，该块归入子表。若已有同实例同类别子表则在该层续接，否则在「最深的开放项」下一层开新子表。同一开放实例的块保持同级；类别不同的块保持为同层类别切换（README 约束 9）。`test_t01_sublist_new_numid_ilvl0` 与聚合用例因此转绿；冻结样例文件未改动。
3. **父项缺失或滞后的降级与诊断**（工作项 3）。运行起始的深层项在无前置父项时按原逻辑降级到局部列表根，并记录 `orphan_list_depth_flattened`（info）；当同一运行内其后出现一个更浅的真实项时，为该孤儿追加 `late_list_parent`（warning，含 `declared_level` 与 `parent_appears_after`），不再静默挂到最近项。`test_t04_child_before_parent_is_reported` 覆盖 `[深层子项][浅层父项]`。深层项在组内不挂最近父项：每个隐式组只含同层项，`_emit_group` 的 `last_by_depth` 回退在同层组内恒为 `None`。
4. **多层嵌套覆盖**（工作项 4）。多层有序嵌套、多层无序嵌套、有序无序交叉嵌套、列表穿插正文四类均有测试：`test_t04_markdown_multi_level_nesting_end_to_end`（三层有序 + 无序内交叉有序 + 穿插正文，树深 1/2/3 与 1/2 正确，正文段不入列）、`test_t04_three_level_nesting_end_to_end`（DOCX 三个新 numId 在 ilvl=0 逐层嵌套）、`test_t04_sublist_new_numid_end_to_end`（两层）。
5. **输出顺序守恒的结构创建修正**（复审后更正口径）。基线里 `transaction._order_stage_decisions` 对同父创建一律按 `-index` 降序落地，再按 index 插入。该组合对锚定既有兄弟的题注是必要的（从尾部回插保持锚点），但对「在新容器中一次创建三个以上兄弟节点」会打乱源顺序：新建父节点的子列表在插入前为空，降序会得到 `[0,2,1]` 类顺序，实测四项平坦列表渲染为 `第一项 第四项 第二项 第三项`。修正为：同批次新建父节点的子创建按升序 index 落地。
   复审更正：T04 的嵌套样例容器都只有两个子项，而两个子项的升序与降序一致，因此该修正**不是**嵌套样例顺序正确的前提，其证据中的「4 项渲染为 `父项一 子项二 父项二 子项一`」只对单容器四项成立。该修正的实际价值是修复任何三项以上新建容器（例如平坦的多项 DOCX 列表）的源顺序。护栏 `test_t04_created_container_preserves_source_order_for_three_or_more_items` 在旧排序下失败、在新排序下通过，已在复审中实测。
   该文件不在 README 架构定案清单，属于 T04 为保证「顺序守恒」所需的最小排序修正，已在此显式声明，并记录为独立工单候选（见残留 12）。
6. **显式列表容器约束覆盖**（承 T03 残留 9/11）。`_validate_state_constraints` 新增对显式 `list` 容器的校验：容器的结构层级为祖先 `list` 容器数量；层级大于 0 且直接父节点不是 `list_item` 时，对其每个已裁决为列表项的直接 `list_item` 子节点产出约束 3（`list_constraint_violation`）。约束 4 对结构层级永不可达（层级每嵌套一步恰好加一），已在文档中说明。`test_t04_explicit_nested_list_without_parent_item_is_reported` 覆盖 `root -> listA -> listB -> itemB`。
7. **树级回读**（承 T03 残留 6）。`audit_list_readback` 在扁平 `(list_kind, numId, ilvl)` 比对之外，用 `_expected_list_tree` 从 AST 容器归属得到期望父链，用 `_level_parent_chain` 从保存的 `w:ilvl` 推导实际父链，不一致产出 `list_parent_chain_mismatch`。该问题与 `list_readback_mismatch` 一起经 `native_stages._native_auditor` 并入 `saved_output_audit` 与发布门禁。`test_t04_readback_detects_wrong_parent_chain` 把 `i2` 的 `w:ilvl` 从 1 改为 0，父链由 `[None,0,None]` 变为 `[None,None,None]`，门禁失败。夹层（产品路径把嵌套项夹回 0）按「render level 表达不了嵌套时期望父项为空」处理，因此真实嵌套转换在夹层下仍通过。
8. **候选评分去留**（承 T03 残留 7）。删除 `_state_candidate.score` 与 `_arbitrate_state_candidates` 的每块最高分预过滤，候选状态完全由 Resolver 的证据类别（`resolver._candidate_strength` 读取 `positive_evidence.kind`）裁决。这是本工单允许的两条路径之一（移除字段并停止把候选描述为「scored」）。`test_t04_state_candidates_are_arbitrated_on_evidence_class` 断言候选不再携带 `score`，并断言结构证据胜过上下文证据、同类别产生 `unresolved` 平局。
9. **pStyle 层级继承**（承 T03 残留 1）。本工单的嵌套裁决以「声明 ilvl=0 + 不同 numId 实例」为输入，未依赖 `effective_ilvl`，因此 `effective_ilvl` 仍未驱动分组，残留保持不变并归 T10。
