## F1 根因与修复后的编号设计

### 根因

模板 `assets/wx_template.docx` 的编号目录：

- `numId 1 -> abstractNum 6`（9 级，`%1 `、`%1.%2`、`%1.%2.%3` …），`word/styles.xml` 把 heading 1 至 heading 6 绑到 `numId 1` 的 ilvl 0 至 5
- `numId 2 -> abstractNum 3`（9 级），绑定 heading 7 至 9
- `numId 3 -> abstractNum 4`（1 级，`lowerLetter`、`%1)`），绑定 `1.1一级列项-编号`
- `numId 8 -> abstractNum 7`（1 级，`decimal`、`%1)`），绑定 `2.1二级列项-有编号`

首轮的 `_effective_numbering_ids` 只把「级数最多的同类实例」重绑给深层角色，于是 `list_decimal` 从 `numId 8` 变成 `numId 1`。`numId 1` 归标题大纲所有，且第 0 层有序项仍在 `numId 3`，因此三个后果同时出现：深层项推进标题计数器；没有第 0 层项落在 `numId 1`，第 1 级永不重启；`%1` 引用的是标题的章节计数器。

### 修复：产出文档合成列表专用编号实例

`normalization._numbering_plan`（取代 `_effective_numbering_ids`）在默认策略下合成**一个**列表专用实例，形如：

```
num_id              = 模板最大 numId + 1                （本模板 22）
abstract_num_id     = 模板最大 abstractNumId + 1         （本模板 10）
deeper_abstract_num_id      = 6   （深层各级克隆自模板大纲）
level_zero_abstract_num_id  = 4   （第 0 层取自模板一级字母定义）
level_zero_num_fmt / lvl_text = lowerLetter / %1)
```

- 有序角色 `list_letter` 与 `list_decimal` 都绑到该实例，`list_letter_abstract` 与 `list_decimal_abstract` 都写 `10`，因此第 0 层与深层共享一套计数器：`%1` 引用列表自身第 0 级计数器，新的第 0 层项重启其下各级。
- 无序角色保持模板绑定（`list_dash 5`、`list_bullet 4`），深层无序仍走夹层路径。
- 实例由 `rendering.materialize_list_numbering` 在加载模板后写入产出文档的 `w:numbering`：克隆指定 abstract，删掉 `w:nsid` / `w:tmpl` 身份元素，剥掉各级 `w:pStyle`（保证没有标题样式借用该实例），并把 `w:lvlRestart` 显式写成 ilvl 0 为 `0`（永不重启）、ilvl k 为 `k`（上一层出现时重启，即 OOXML 默认语义的显式形式）。
- 第 0 层定义取自 `abstractNum 4`，因此一级列项的可见外观（`a)`、缩进、Times New Roman）与修复前一致；`w:num` 与 `w:abstractNum` 均为新增元素，模板文件未落盘修改（测试 `test_t08_list_only_instance_is_synthesized_in_the_produced_part` 比对转换前后 `assets/wx_template.docx` 的 sha256）。

## 默认策略现在的行为（变更记录）

默认 `--list-policy wx-default-v2` 与首轮相比只改了一处，即有序项绑定的编号实例；可见编号的规则如下，读到变更记录的使用者不会被意外：

- 单层有序列表：仍是 `a)`、`b)`、`c)`（`1.1一级列项-编号`），可见外观与修复前一致；保存 XML 里的 `w:numId` 从模板的一级字母实例 `3` 变成列表专用实例 `22`，`w:ilvl` 仍为 `0`。
- 多层有序列表：第 0 层为 `a)`、`b)`，第 1 层及更深为该列表自身第 0 级字母加自身层级计数，例如 `a.1`、`a.1.1`、`b.1`。深层项的可见标记来自列表专用大纲实例，模板里没有「第 1 级为 decimal `%1)`」的实例，因此不会显示成独立的 `1)`。
- 深层无序列表：模板没有多级 bullet 实例，仍夹层到 `w:ilvl 0` 并发出非阻断诊断 `list_render_level_clamped`。
- 单层无序列表：不变（`list_dash` 5 / `list_bullet` 4）。
- 顶层有序编号在整个文档内连续（第 0 层 `w:lvlRestart=0`），与修复前共享 `numId 3` 的行为一致；「每章节遇到标题后重启」在保存输出里仍未落地（无 `w:startOverride`），这一点未因本工单改变。
- 受保护内容、普通文档与 T07 规则不受影响（见「回归复验」）。

## ListPolicy 接口与默认映射

`scripts/wxdf/list_policy.py`（新增叶子模块，`wxdf.normalization` 原样再导出下列名字）：

```python
@dataclass(frozen=True)
class ListProjection:
    render_level: int
    style_role: str

@dataclass(frozen=True)
class ListPolicy:
    name: str
    ordered_roles: tuple[str, ...]      # 索引 i 对应 render level i，最后一档向下重复
    unordered_roles: tuple[str, ...]
    chapter_scoped_sequence: bool = False
    bind_multilevel_numbering: bool = False

    def project(self, list_kind: str, semantic_level: int) -> ListProjection: ...
    def deeper_roles(self) -> tuple[str, ...]: ...

def default_projection(list_kind: str, semantic_level: int) -> ListProjection: ...
```

- `project` 是唯一投影入口：按 kind 取角色表，返回 `(render_level, style_role)`。两个随产品发布的策略都保留真实语义层级，因此投影没有层级上限；**FIX 轮删除了 `ListPolicy.max_level` 与 `ListPolicy.roles`**：前者只被 `project()` 读取且没有任何策略设置它，后者从未被调用，README 字段表里的两级投影只是举例，两个策略都不做夹层。
- `normalize(..., strategy=...)` 的 `strategy` 既接受策略名（`legacy` / `wx-default-v2`），也直接接受一个 `ListPolicy` 实例，因此换策略不需要注册。
- 模板加三级样式时只改策略：把 `ordered_roles` 扩为 `("list_letter","list_decimal","list_roman")`，第 2 层自动落到 `list_roman`，`semantics/lists.py` 不动（由 `test_t08_list_policy_is_swappable_for_a_third_template_level` 验证）。

默认 `wx-default-v2` 的映射（`(kind, level) -> (render_level, style_role)`）：

| kind | semantic_level | render_level | style_role |
| --- | --- | --- | --- |
| ordered | 0 | 0 | `list_letter`（一级列项-编号，`a)` 外观） |
| ordered | >= 1 | = semantic_level | `list_decimal`（二级列项-有编号样式；编号实例与第 0 层共用列表专用实例） |
| unordered | 0 | 0 | `list_dash`（一级列项-无编号） |
| unordered | >= 1 | = semantic_level | `list_bullet`（二级列项-无编号） |

`legacy` 策略映射相同，但 `chapter_scoped_sequence=False`、`bind_multilevel_numbering=False`，即保持历史行为（逐层样式、模板自带编号实例、目录序号直取源序号），不合成任何实例。
