## 用户裁定：治理冲突已解决

本工单首轮与 FIX 轮的默认策略与 `AGENTS.md` 关键决策记录 1 冲突，曾作为阻断残留记录。用户在 2026-09-15 裁定，`AGENTS.md` 关键决策记录 1 现在为：

> ### 1. 列表最多两级，按种类落在对应层级样式
> - 有序列表嵌套：第一层级用一级有序列表样式（a) b) c) 格式），第二层级用二级有序列表样式（1) 2) 3) 格式）
> - 无序列表嵌套：第一层级用一级无序列表样式，第二层级用二级无序列表样式
> - 有序与无序交叉嵌套：先出现的种类为一级，后出现的种类为二级，按种类是否已出现过判定，优先一级样式再二级样式
> - 最多识别两级列表。层级更深时夹到二级并产出诊断；更深的结构应改用标题层级表达，不用列表
> - 每章节遇到标题后从 a) 重新开始
> - 2026-09-15 用户裁定：本决策取代原先「所有有编号的列项统一使用一级列表样式」的表述，嵌套项按上述两级模型处理

裁定对代码的具体含义：

1. `ListPolicy.max_level = 1` 是产品默认 `wx-default-v2` 的层级上限。语义层级 0 投到渲染层级 0，用该种类的第一级样式；语义层级 1 或更深投到渲染层级 1，用该种类的第二级样式（有序 `list_decimal`，无序 `list_bullet`）。
2. 语义层级深于 1 的项夹到渲染层级 1，并产出可观察的 `list_render_level_clamped` 诊断，提示用户改用标题层级。
3. 第二级角色绑回模板自带实例：有序第二级 `list_decimal -> numId 8`（abstract 7，`%1)` decimal），无序第二级 `list_bullet -> numId 4`（abstract 5，bullet）。不再合成大纲实例，嵌套有序项显示模板设计的 `1)`，首轮与 FIX 轮的 `a.1` 大纲编号被移除。
4. 每个模板列表实例都是单级，因此两级模型下每个列表项发射的 `w:ilvl` 都是 0，两级由样式与实例区分。这是设计结果，不是夹层缺陷，不发诊断。

首轮与 FIX 轮的实现（重绑模板多级实例、再改成合成列表专用实例 `numId 22 / abstract 10`）都不符合本次裁定，已由本轮替换。FIX 轮修复的真实缺陷（深层有序项与标题大纲实例 `numId 1` 同号）在本轮不再出现，因为不再有深层有序项绑到多级实例：两级各自绑模板的单级实例，标题实例 `numId 1 / numId 2` 与列表实例 `numId 3 / 8 / 5 / 4` 无交集。

## ListPolicy 接口与默认映射

`scripts/wxdf/list_policy.py`（叶子模块，`wxdf.normalization` 原样再导出 `ListPolicy` / `ListProjection` / `list_policy` / `LIST_POLICIES`）：

```python
@dataclass(frozen=True)
class ListProjection:
    render_level: int
    style_role: str
    clamped: bool = False

@dataclass(frozen=True)
class ListPolicy:
    name: str
    ordered_roles: tuple[str, ...]      # 索引 i 对应 render level i
    unordered_roles: tuple[str, ...]
    chapter_scoped_sequence: bool = False
    max_level: int | None = None        # None 表示不设上限

    def project(self, list_kind: str, semantic_level: int) -> ListProjection: ...
```

- `project` 是唯一投影入口：按 kind 取角色表，`render_level = semantic_level`，当 `max_level` 已设且层级更深时夹到 `max_level` 并把 `clamped` 置真，`style_role` 取该渲染层级的角色。`clamped` 是渲染器发出 `list_render_level_clamped` 的唯一依据，因此只有「深于策略上限」触发诊断，「单级实例的第 1 层」不触发。
- `normalize(..., strategy=...)` 的 `strategy` 既接受策略名（`legacy` / `wx-default-v2`），也直接接受一个 `ListPolicy` 实例，因此换策略不需要注册。
- 模板加三级样式时只改策略：把 `ordered_roles` 扩为 `("list_letter","list_decimal","list_roman")` 并保留 `max_level=None`，第 2 层自动落到 `list_roman`，`semantics/lists.py` 不动（由 `test_t08_list_policy_is_swappable_for_a_third_template_level` 验证）。

默认 `wx-default-v2` 的映射（`(kind, semantic_level) -> (render_level, style_role, clamped)`）：

| kind | semantic_level | render_level | style_role | clamped |
| --- | --- | --- | --- | --- |
| ordered | 0 | 0 | `list_letter`（一级列项-编号，`a)`） | 否 |
| ordered | 1 | 1 | `list_decimal`（二级列项-有编号，`1)`） | 否 |
| ordered | >= 2 | 1 | `list_decimal` | 是 |
| unordered | 0 | 0 | `list_dash`（一级列项-无编号） | 否 |
| unordered | 1 | 1 | `list_bullet`（二级列项-无编号） | 否 |
| unordered | >= 2 | 1 | `list_bullet` | 是 |

`legacy` 策略角色映射相同，`chapter_scoped_sequence=False`、`max_level=None`，即保持历史行为（逐层样式、模板自带编号实例、目录序号直取源序号、不设层级上限），供策略替换能力测试与历史调用使用；产品 CLI 不暴露该取值。
