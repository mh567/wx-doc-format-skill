## 失败原因分类

### 证据字段缺失(影响 9 个 fixture)

当前 `analyze_lists` 输出的列表项仅包含以下字段:

```
item_id, list_id, parent_item_id, scope_id, source_marker,
source_ordinal, source_sequence_id, list_kind, target_ordinal,
generated_anchor_required, anchor_reason, explicit
```

缺少 spec 要求的 14 个证据字段:

```
source_ilvl, effective_ilvl, semantic_level, render_level,
start_value, sequence, restart_scope, num_id, abstract_num_id,
num_fmt, lvl_text, w:ind, suffix, p_style_ref
```

### 结构错误(影响 2 个 fixture)

| fixture | 当前行为 | 期望行为 |
|---------|---------|---------|
| `test_t01_sublist_new_numid_ilvl0` | 新 numId + ilvl=0 子列表的 `parent_item_id` 为 `None`(扁平化到文档根) | 子列表项应挂到父项 `p1` 下 |
| `test_t01_missing_numbering_definition` | 编号定义缺失时产生 `missing_numbering_definition` 诊断(正确),但该 fixture 原始断言期望 `invalid_numbering_definition` | 修正为接受任一编号诊断码 |

### 重启表达式(影响 1 个 fixture)

当前列表条目使用 `source_start`(整数)和隐式 `restart_hint`(布尔值)。spec 要求列表条目携带 `start_value / sequence / restart_scope` 表达式对象,使得从非 1 起始的序列能被精确表达。

## 真实样例来源

fixture 构造基于以下既有文档与代码路径的问题模式:

- `input/test_baseline.md` 中的 `6.3 标准化注册时序流程` 类标题段落
- `scripts/list_detector.py` 的编号分析在跨 numId、ilvl=0 子表、编号缺失时的已知局限
- `scripts/wxdf/semantics/lists.py` 中 `analyze_lists` 对 `explicit_depth`、`numbering_definition_ref`、`restart_hint` 的当前处理方式
- `scripts/wxdf/semantics/protected.py` 中 `_is_protected` 仅识别 `heading / toc` 前缀的段落样式,不识别自定义标题样式

## 未解决问题(open items)

1. **证据字段的写入层**: 当前 fixture 在 `evidence` 字典中直接写入 `source_ilvl / num_fmt / lvl_text` 等字段,但 `analyze_lists` 并不消费这些字段。T02 需在 `parsers.py` 的原生编号目录中产出这些字段,并在 `lists.py` 中将它们透传到输出项。
2. **段落样式 `pStyle→ilvl` 继承**: 当前 `analyze_lists` 不处理 `w:lvl/w:pStyle` 关联。T02 需在原生编号目录中解析 `pStyle` 到 `ilvl` 的映射,并在证据中提供 `p_style_ref`。
3. **`lvlRestart / startOverride`**: 当前编号目录不支持这两个 OOXML 字段。T02 需补全。
4. **`w:ind` 编号级缩进**: 当前证据层不区分文档级与编号级 `w:ind`。T02 需补全。
5. **`suffix`**: 当前证据层不捕获编号后缀分隔符。T02 需补全。
6. **`w:ind` 字段命名**: spec 字段清单使用 `w:ind`(含冒号),在 Python dict 键中直接使用。T02 落地时需确认该键名不会与序列化/下游消费方冲突。
7. **`render_level` 的 ListPolicy 投影**: 当前实现没有 `ListPolicy` 抽象。T08 才会提取。T01 fixture 仅断言字段存在,不断言投影值。
8. **`AMBIGUOUS` 候选状态**: 当前 `analyze_lists` 不产出候选状态枚举。T02 需在候选结构中加入 `candidate_state` 字段。
