## FIX 轮

独立复审发现一个 BLOCKER、一个 MAJOR 与四个 MINOR，本轮（FIX 轮）逐一修复：

- F1（BLOCKER）回读文本提取只拼 `w:t`，丢掉了 `w:br` 的软换行，导致带软换行的普通列表续接被 `every_block_preserved_once` 判为不一致并让转换 `status=failed`。修复：`_paragraph_text` 按内联投影输出 `w:br`/`w:cr` 为 `"\n"`、`w:tab` 为 `"\t"`（与 `check_saved_output.paragraph_text` 一致）。
- F2（MAJOR）`_make_phase_batches` 对 `batching == "single"` 无条件返回 `[items]`，空收集时是 `[[]]`（真值），于是干净文档也走了一次全量提示词的 LLM 调用。修复：空单批次返回 `[]`。
- F3（MINOR）`every_block_preserved_once` 只比较列表项文本，名字却声称覆盖每个块；证据还写了一个不存在的 `list_readback_duplicate_item`。修复：重命名为 `list_items_preserved_once`，问题码 `list_item_preservation_mismatch`，并在代码与证据中注明非列表块重复由 `check_saved_output.paragraph_order_changed` 兜住。
- F4（MINOR）`low_confidence_has_diagnostics` 与 `no_silent_ambiguity` 是空洞或不可达的。修复：前者改为双向检查（低置信度记录必须指向证据里真实存在的节点，且每个 ambiguous 证据节点必须有裁决或记录）；后者改为检查每条未解决候选都留下了 `ambiguous_list_state` 记录且状态未报 `completed`。
- F5（MINOR）rebuild 失败时四项语义不变量被写成 `True`，无法区分「已检查通过」与「跳过」。修复：跳过时写成 `None`，并新增 `semantic_rebuild_checked` 布尔位。
- F6（MINOR）`_actual_render_levels` 只要有一行的样式映射不回投影角色就整体返回不可用，从而把 `ast_readback_tree_agrees` 变成通过。修复：逐行降级比较，且表外的未映射样式单独报 `list_render_style_unmapped`（表格单元格内的列表项使用 `表正文` 属设计行为，单列为不可由样式恢复层级，不算篡改）。

## 不变量覆盖

| 不变量（README） | 检查方式与真实问题码 | 不能覆盖的部分 |
| --- | --- | --- |
| 每块恰好保留一次 | `list_items_preserved_once`，问题码 `list_item_preservation_mismatch`：**仅**逐项比对回读列表项文本与语义列表项文本（读序一致、一一对应） | 非列表块（正文/标题等）的重复或丢失不在此列，由 `check_saved_output.paragraph_order_changed` 兜住 |
| 深层项必有父项 | `_semantic_rebuild_invariants` 读取重解析结果的 `rebuild["items"]`，问题码 `list_deep_item_without_parent` | 只看回读树的 `parent_item_id`，看不到渲染阶段丢掉的源块；渲染层级链（`ast_readback_tree_agrees`）是另一条检查 |
| 续接正文有 `owner_item_id` | `_semantic_rebuild_invariants` 读取 `rebuild["continuations"]`，问题码 `list_continuation_without_owner` | 同上，只看回读树 |
| 编号模拟值与源可见序列一致 | `_saved_number_sequence`，问题码 `list_numbering_sequence_mismatch`：按 `(numId, ilvl)` 分组模拟可见计数，读 `w:start` / `w:lvlRestart` / `w:lvlOverride`（含不带 `w:lvl` 的纯 `w:startOverride`） | 多个 `w:num` 实例共享同一抽象定义时的逐实例 override 交互边界未覆盖 |
| AST 与回读树一致 | 扁平 `(kind, numId, ilvl)` 序列比对（`list_readback_mismatch`）；发出层级父链 `list_parent_chain_mismatch`；样式恢复的渲染层级链 `list_render_level_mismatch` 与 `list_render_style_unmapped` | 角色在多个投影层级复用时渲染链整体跳过；表格单元格内列表项的样式是 `表正文`，其层级不可由样式恢复 |
| 低置信度决策都有诊断 | `_semantic_rebuild_invariants`，问题码 `list_low_confidence_without_diagnostic`：每条 `low_confidence_list_marker` 降级必须指向证据里存在的节点（幽灵记录即失败），且每个 `numbering_status == "ambiguous"` 的证据节点必须有裁决或记录 | 只检查重解析后的输出侧记录一致性；源侧低置信度集合无法从保存的 DOCX 反推，故源侧门控不在此检查内 |
| 普通模式不静默接受歧义 | `_semantic_rebuild_invariants`，问题码 `list_silent_ambiguity`：每条 `state_unresolved` 候选必须留下匹配的 `ambiguous_list_state` 记录，且状态不得报 `completed` | 不重新裁决冲突本身 |

两级模型（2026-09-15 用户裁定）下两个有序层级的 `w:ilvl` 都是 0，层级信息落在样式与编号实例上，因此回读层级链改由样式角色恢复。逐行降级比较：带投影角色的行参与层级与父链比对，表内或无法映射的行不参与。表外样式映射不回任何投影角色的行单独产出 `list_render_style_unmapped`，因此一次允许的样式改动无法关闭比较；只有角色本身在多个投影层级复用（例如 `legacy` 策略复用 `list_decimal` 于 1、2 层）时整链才合法跳过，此时仍由扁平序列与编号序列比对守护。

## LLM 门控边界

- `list_detect` 只在**已存在多候选**的歧义片段上介入：无歧义片段时 `_collect_list_detect_batches` 返回 `[]`，`_make_phase_batches` 对空单批次返回 `[]`，因此 `enhance_document_model` 与文件协议都不调用模型（F2）。
- 介入时以单批次的 `blocks_override` 交付，范围恰为这些片段，不回写整棵列表结构。
- `_validate_list_detect_patch` 拒绝改写尚无多候选项的干净块，只接受受限的歧义决策补丁，从而把 LLM 的输出限制在 Resolver 全局约束之内。
