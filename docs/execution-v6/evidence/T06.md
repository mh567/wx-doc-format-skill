## 序列身份口径

本工单沿用并最终确定已发布的拼写 `docx-sequence-{num_id}-{abstract_num_id}`（无 `abstract_num_id` 时为 `docx-sequence-{num_id}`），用于所有对外可见字段：列表组 `source_sequence_id`、`sequence`、重启表达式的 `sequence`，以及本工单新增的合并记录 `merged_sequences`。该拼写与 `parsers._numbering_sequence_id` 和 `lists.json_sequence_id` 一致，T01 冻结样例与 T02 目录测试都断言这一拼写。

内部裁决键保留 T04 引入的 `num:{num_id}:abstract:{abstract_id}`（`lists._numbering_sequence`），只用于 `_resolve_sublist` 与合并/拆分的实例比较，不对外暴露。这样对外只有一个编号身份拼写，内部比较键的改动不会外泄到报告合同。

拆分身份（FIX 轮 F2）：一次拆分会产生两个组，若复用同一实例，两组的 `source_sequence_id / sequence / restart_scope` 完全相同，拆分只存在于 `group_boundary.kind`。FIX 轮新增加性字段 `sequence_split_index`（`int`，默认 0）作为身份扩展：它是在同一 `(source_sequence_id, list_kind, parent_item_id, depth)` 槽位内的组序号，首个组为 0，从它拆出的组为 1、2 等。`sequence` / `source_sequence_id` 的 `docx-sequence-{num_id}-{abstract_num_id}` 拼写保持不变，`sequence_split_index` 与 `group_boundary.kind=sequence_split` 一起使拆分在已发布的 `list_semantics` 合同上可观测。`list_semantics` 合同版本 2.1 保持，只做加法。

`restart_scope` 口径（FIX 轮 F3）：按 README 证据字段清单由 `num_id` / `abstract_num_id` 派生（`abstract:<id>` 或 `num:<id>`），组、`restart_expression` 与逐项关系三者一致，不再与 `sequence` 重复。

## 工作项落地

1. **重启、指定起始值、同级继续编号**（工作项 1）。同级续接由 `_sequence_continues_open_group` 判定：同一父、同类别、`restart_hint` 显式为 False、`num_fmt` 与归一化 `lvlText` 一致，即视为同一逻辑序列并续接前一组；重启表达式 `restart_expression` 从 `start_value / sequence / restart_scope` 扩展出 `lvl_restart / start_override / restart_policy / merged_sequences`（README 约束 10 的输入），起始值在序列边界由 `start_value` 承载并在拆分处重置。
2. **拆 numId 合并 / 复用 numId 拆分**（工作项 2，README 约束 8）。跨 numId 续接：一级块若续接开放组则跳过 `_resolve_sublist`，直接并入开放组，组保留首个实例为规范身份并把后续实例记入 `merged_sequences`。同 numId 复用：同一开放实例再次出现且 `restart_hint` 为真时 `split_sequence` 成立，开启新组并产出 `sequence_split` 边界。FIX 轮 F1 补齐 `depth > 0` 路径：实例变更分支不再无条件合并，先判同一续接证据，不续接时同样产出 `sequence_split`，因此重启的兄弟子表拆成两条序列。FIX 轮 F2 增加 `sequence_split_index` 使复用实例的拆分在身份上可区分。序列身份对外拼写固定为 `docx-sequence-{num_id}-{abstract_num_id}`。
3. **编号定义缺失或损坏降级**（工作项 3）。降级路径保持不变：`_contract_downgrades` 仍产出 `missing_numbering_definition` / `invalid_numbering_definition` 诊断与 `downgrades` 记录，`_state_candidates_for_paragraph` 的 `contract` 候选压过 `heuristic` 列表候选，块保持正文且源内容保留（`fallback.preserve_source_content=true`）。守卫测试 `test_t06_damaged_numbering_definition_degrades_and_preserves_source` 覆盖。
4. **子表随父重启 / 跨父继续两种策略**（工作项 4）。`_restart_policy_for_level` 由 `w:lvlRestart` 决定：`0` 为 `continue_across_parents`，其余（含缺省）为 `restart_with_parent`。策略写入组 `restart_policy`，并在 `continue_across_parents` 时用 `continuation_groups` 让第二个父项下的子表从上一组的 `start_value + item 数` 继续。两种策略各有一个单元测试与一个真实 DOCX 端到端测试。
