## 实施摘要

### 模块级导入改为「优先直连、不可用时延迟绑定」

`scripts/main.py` 保留三处原始导入位置，各自包裹 `try`：

| 位置 | 直连导入 | 不可用时的回落 |
| :--- | :--- | :--- |
| 原 `docx_pipeline` 与 `md_pipeline` 与 `model_normalization` 段 | 三个模块六个符号 | `_deferred_legacy_callable` 包装 |
| 原 `docx_render` 段 | `render_docx_direct` | 同左 |
| 原 `template_finalizer` 段 | `apply_template_finalizer`、`extract_template_toc_fragment` | 同左 |

`_deferred_legacy_callable(module_name, attribute)` 返回一个 `*args, **kwargs` 转发函数，首次调用时 `import_module` 并转发。回落只在模块确实不可导入时发生，因此：

- 正常运行时 `main.parse_md_to_model is md_pipeline.parse_md_to_model` 为 `True`，其余四个绑定同样为 `True`。绑定的是原函数对象本身，调用点与签名均未改动。
- 导入顺序与 T01 实现完全一致，旧 parser、旧 normalization、旧 renderer、旧 finalizer 只在原位置加载。
- 被拦截时 `import main` 成功，且六个拦截模块都不进入 `sys.modules`。

### 模板 TOC 片段自持

`wxdf/template.py` 新增 `extract_template_toc_fragment(document)`，直接读取模板 OOXML：定位含 `\bTOC\b` 指令的 `w:sdt`，连同紧随其后的分页 `w:p` 一起深拷贝。对同一模板，该实现与旧 finalizer 的实现产出的片段**逐字节相同**：

```
fragment count native/legacy: 2 2
byte identical: True
```

### 题注语义物化

`wxdf/semantics/captions.py` 的 `collect_caption_candidates` 在原资格判定之外，为每个尚无题注的题注合格目标追加两个候选：

- `create_node`：生成题注块，`role="caption"`、`caption_type`、`target_id`、`generated_by="caption_semantics.sequence_caption"`、`generation_basis=[target_id]`。表题注插入到表格之前的下标，图题注插入到图形之后
- `update_association`：写入 `{"kind": "caption_target", "source_id": <题注块>, "target_id": <目标块>}`

这正好对应 `docs/modular-pipeline-migration-v3.1.md` 的条目 4「确定性新增题注表示为带 `generated_by` 和 `generation_basis` 的生成节点」，并且复用既有 `update_association` 事务处理器与既有 `caption_target` 校验规则（`validation.py:377`、`506`）。目标已有题注时不重复生成。

### 题注渲染

`wxdf/rendering.py` 对 `role == "caption"` 的段落写入「前缀 run + `w:fldSimple SEQ Table \* ARABIC` + 空格 run」，段落样式取模板的 `caption` 角色解析结果。同时把 `render_map[node_id]["text"]` 置为该段落的可见文本（含域占位数字），使 `check_saved_output` 的段落文本比较无需为题注开特例。

原生产物与 legacy 产物的题注段落 XML 结构一致（`w:pStyle w:val="12"`、`表 `、`SEQ Table \* ARABIC`、尾随空格）。

### 图片的 AST 所有权

原生解析把图片放在 `paragraph.inline_content` 中，Source AST 因此没有图片节点，图题注既没有可用目标，也没有 `SEQ Figure` 输出。`source_ast.py` 的 `_inline_image_nodes` 在构建阶段为每个行内图片生成一个显式 `image` 节点：

- `resource_id` 与 `alt_text`，`alt_text` 为空时由图片部件的文件名补足，保证块级 image 的非空校验
- `source_ref` 取该图片部件自身的引用（`media/...` 或 `word/media/...`），可直接用于资源解析与题注目标
- `generated_by="source_ast.inline_image"` 与 `generation_basis=[<来源段落 id>, <行内下标>]` 记录物化来源
- 节点插入在承载该行内图片的段落之后

原段落完整保留：文本、其他行内 token、行内图片与顺序都不变。这满足 `tests/test_issue3_acceptance.py` 的既有合同（行内图片所在的段落在列表中保留、承载列表编号）与 `tests/test_issue7_acceptance.py` 的混合行内顺序合同，source AST 投影与保存后审计合同不变。

渲染由承载行内 token 的段落负责，语义 image 节点不再输出第二张图片，因此 `inline_shapes` 数量不变。

### 作者题注物化

`collect_source_caption_semantics` 能识别作者题注，但作者题注在 Source AST 中原本仍是 `role="body"` 的段落，既没有 `target_id`，也不会进入 `_captioned_targets`，于是同一目标还会再插入一个 `inline_content` 为空的 `native-caption-*`。

`source_ast.py` 的 `_authored_caption_materialization` 在构建阶段消除该缺口。它只消费题注语义模块的公开结果，作者题注段落因此成为真正的题注块：

- 保留原有 `source_ref`
- 保留原有可见 `inline_content`
- 增加 `role="caption"`、`caption_type`、`target_id`
- 在 `document.associations` 写入 `caption_target`

判定收敛于 `status == "associated"` 且目标可解析为表格容器或图片节点的题注。图题注的目标是承载行内图片的段落，经 `image_targets` 映射到该段落物化出的 image 节点，因此 `caption_type="figure"`、`target_id` 指向有效 image，`caption_target` 关联随之成立，位置在图片之后。

未带题注的图片由 `collect_caption_candidates` 的图片分支生成题注，节点排在图片之后，候选的 `target_source_refs` 为该 image 节点的 `source_ref`，并且不产生重复题注。生成的图题注与表题注一样只有编号，正文可由 T03 的 `caption_gen` 能力经 ContentOverlay 补齐。

`document-structure` 会为每个段落提出默认 `body` 角色，作者题注的角色因此在 `collect_caption_candidates` 中复述一次，与 `legacy_capability.py` 既有的 `update_role` 题注候选写法一致。`caption_type` 与 `target_id` 由构建阶段写入。

关联候选的前置条件不再为空。`caption-association-*` 的 `target_node_ids` 指向目标表格或图形，`target_source_refs` 为该块 `source_ref` 的深拷贝，事务的 source reference 前置条件因此有实际校验对象。

## 结构断言调整

`tests/test_issue3_acceptance.py` 的两项结构断言在本工单实施中失败。Codex 扩展了路径声明，两项断言已按生成题注块调整，断言意图不变。

### 失败现象

```
FAILED tests/test_issue3_acceptance.py::test_l07_first_table_and_sublist_get_one_evidenced_anchor
FAILED tests/test_issue3_acceptance.py::test_l09_merged_and_nested_table_cells_are_unique_and_scope_local
```

### 根因

两项失败都由同一个新增节点引起：题注合格的数据表现在会得到一个插在它前面的生成题注块。

- `test_l09` 第 530 行断言 `document["children"]["root"]` 的块序列严格等于 `[("block", "外部一"), ("table", None), ("block", "外部二")]`。题注块使该序列多出一项。
- `test_l07` 第 177 行取 `list_item` 中第一个不以 `generated-anchor-` 开头的子节点并断言它是表格。题注块排在该位置。

两项断言编码的是 T02 之前的不变量「题注只存在于渲染期，不进入 source AST 树」。该不变量正是 T02 要收口的部分。题注必须排在表格之前（`caption_above_table`，`validation.py` 与 `audit_caption_placement` 均如此要求），所以任何物化方案都会触发它们。

legacy 链路对同一夹具本就产出题注，说明这些表确实是题注合格目标：

```
l09.docx  legacy SEQ Table = 1
l07.md    legacy SEQ Table = 1
```

`tests/test_issue3_acceptance.py:177` 改为按块类型选取表格，不再依赖子节点位置：

```python
table_child = next(
    child_id
    for child_id in document["children"][first_item]
    if document["blocks"].get(child_id, {}).get("block_type") == "table"
)
```

## 限制与风险

- `except ImportError` 会在旧模块因其他原因不可导入时同样回落到延迟绑定。此时错误推迟到 legacy 路径真正调用时抛出，不会静默成功
- 生成的图题注与表题注一致，只有前缀与 `SEQ` 域，正文留空。题注正文由 T03 的 `caption_gen` 能力经 ContentOverlay 补齐
- 语义 image 节点的 `generated_by="source_ast.inline_image"` 是渲染层的跳过依据。该字段同时满足 AST 2.0 对 `source_ref` 与 `generated_by` 的任一要求
- 作者题注的角色由题注 Module 复述一次，依赖该 Module 的候选排在 `document-structure` 之后。候选顺序由 `_native_candidate_set` 固定，与 `legacy_capability.py` 既有的 `update_role` 题注候选写法一致
- 题注段落渲染为单一文本 run，作者题注内的行内标记与链接不进入题注文本。该限制与 legacy 的题注渲染一致
- 该仓库 legacy 产物与报告对输出目录的使用历史敏感，对照实验必须在同一输出目录交替运行才有可比性
- `_build/` 与 `paseo.json` 未改动，`git status --short` 只显示本工单四个改动文件与既存 `?? scripts/.venv`
