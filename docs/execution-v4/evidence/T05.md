# T05 原生审计后复核与候选发布证据

## 状态

T05 实施及独立审查修复轮 3 已完成，等待主 Codex 复审。

## 实现边界

1. `modular_review` 以 `ReviewEvaluator` 合同开放，运行时在 Auditor 与 Publisher 之间注册 `native-reviewer`。
2. Auditor 生成稳定 code 和 AST 目标。明确安全的 `heading_level_jump` 可修复，未知 code 默认不可修复。
3. Reviewer 以审计后基线构造 ReviewPacket，在隔离候选修订中应用裁决、重新规范化、重新渲染并复审。
4. 内容摘要覆盖 document children 顺序、containers、associations、resources、正文块及 overlay。未获授权的内容、顺序、资源、关联或覆盖变化均以 `content_changed` 回滚。
5. 正式输出及 `publish_bundle` 多产物通过暂存、备份和恢复形成失败原子提交。任何替换失败均保留全部原正式产物。
6. all 文件模式支持 relation 等待及 post-audit C 等待。同一审计后 revision 用于 model、item、ReviewPacket baseline 与 response base identity。
7. ledger revision、StageSnapshot、`transaction_content_digests`、`applied_transactions` 和 response binding 使用同一 canonical transaction content digest，并在终态快捷重放前交叉验证。
8. C 响应被策略拒绝或候选事务异常时，checkpoint 保存可幂等重放的 `rolled_back` 终态，正式输出保持原字节。
9. post-audit 请求追加使用可恢复 journal，覆盖替换前 TOCTOU 和请求文件已替换但 checkpoint 尚未保存的崩溃窗口。
10. 发布构建清单和烟测消费已开放的 T05 `modular_review` 合同。
11. ReviewPacket 为每个候选目标声明 `allowed_operations` 和 `property_scope`。Reviewer 在事务前校验目标、操作和值域，并在复审时比较授权范围外 AST 语义。
12. 正式多文件、checkpoint 和 bundle 共享 generation journal。prepared 状态恢复旧 generation，committed 状态完成新 generation，各目标父目录可在下一次入口恢复同一事务。
13. 终态 checkpoint 从 ledger revision 内容重算 canonical digest。未版本化 T04 Checkpoint 2.0 通过窄迁移升级，未知版本拒绝。
14. 后续请求追加在检查、替换及 checkpoint 提交全过程持有排他锁。嵌套 checkpoint generation 先恢复，再处理 append journal。
15. 合法 `move_node` 依据目标外节点的父边与相对顺序校验，允许兄弟节点被动索引位移。
16. 正式 DOCX、辅助 JSON 及 terminal checkpoint 由同一 generation journal 提交，启动恢复依据调用方明确提供的完整可信目标集合。
17. journal 内 target、staged、backup 和 journal copies 均按可信目标与 transaction ID 复算。越界路径及同目录无关目标在任何文件变更前拒绝。
18. canonical transaction digest 纳入 revision status 与 supersedes；legacy T04 迁移先从 SourceFacts 重放 ledger 并核对 AST、overlays、presentation 与 transaction identity。
19. heading repair 的 allowed values 固定为 `role=heading` 与 finding `expected_level`，越权值无法进入候选事务。
20. append recovery 与 append 共用 checkpoint 及 request 排他锁；`fcntl` 与 Windows 锁后端均通过 guarded import 暴露相同接口。
21. bundle 保留名与 marker identity 在发布和恢复边界校验，可信目标范围内的 transaction-shaped pre-journal staging leftovers 可安全清理。
22. native CLI 仅在 kernel 已随 terminal generation 发布 report 时跳过重复写入，release report 使用原有 sanitizer 后进入同一 generation。

## 关键验收证据

1. 内容调序、容器、关联、资源、正文块和 overlay 的未授权变化全部回滚；显式 `move_node` 只允许对应层级位置变化。
2. bundle 目录交换失败与 native 多文件替换失败均恢复全部旧产物。
3. all 文件模式经历 relation 等待、review 等待和最终接受，正常外部实现可仅依据请求身份生成有效响应。
4. 测试直接比较 relation 与 review transaction ID、ledger digest、StageSnapshot digest、applied transaction digest 及 response binding proof。
5. 已完成或已回滚 checkpoint 在快捷重放前重新校验上述交叉关系；篡改 ledger digest 会返回 `transaction_state_mismatch` 且不修改正式输出。
6. 被拒绝的 C 响应保留于 checkpoint 且不标记 applied；relation 响应继续绑定 relation transaction。重复 resume 保持 checkpoint 和正式输出字节不变。
7. journal 故障注入覆盖 checkpoint 保存前进程退出；下一次 resume 自动恢复请求文件。替换前并发改写触发 `request_identity_conflict`。
8. 真实 Markdown H1 到 H3 输入经 production audit 产生 repairable finding，进入 C 流程并修复为 H2，无审计 monkeypatch。
9. 候选事务冲突返回 `rolled_back`、`candidate_transaction_failed` 及审计异常证据，基线仍被选择。
