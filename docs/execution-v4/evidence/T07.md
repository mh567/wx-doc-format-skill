## 实现边界

1. 根 `SKILL.md` 收敛为公开可执行规范源，仅保留触发、模式、平台启动、命令、审计、停止条件和人工复核。
2. `packaging/nuitka/public/SKILL.md` 与 `packaging/nuitka/public-repo/SKILL.md` 为根规范的字节一致快照。
3. 在线组装和离线包组装均直接复制根 `SKILL.md`，测试同时检查源码快照和生成产物字节。
4. 公开在线目标仅含 `macos-arm64` 与 `kylin-v10-arm64`。Windows required 参数返回 `ValueError`，公开树不再包含 PowerShell launcher 或 Windows 目标声明。
5. 在线与离线 manifest 均声明 `public_summary` 合同。在线 manifest 的 `platforms` 映射是 available 与 unavailable 兼容字段的唯一派生来源。
6. 在线和离线 POSIX launcher 均在缓存、下载或 runtime 执行前读取当前平台状态。macOS accepted 继续，Kylin candidate 输出 `WXDF-W-RUNTIME-CANDIDATE` 后继续，unavailable、缺失、未知和损坏状态以退出码 3 停止。
7. release 报告保留递归脱敏兼容行为，并增加 `schema_version=1.0` 的路径无关 `public_summary`。摘要固定包含 status、pipeline、profile、list_policy、audits、unexpected_styles_count、manual_review_required 和 diagnostic_codes。
8. `packaging/nuitka/build_distribution.py` 的历史 Windows 构建入口保持原状，T07 未将其纳入公开发布门禁。

## 独立审查修复

独立规格与标准审查发现三项交付风险，本提交在既有授权范围内闭环：

1. Windows runtime 构建身份继续保留在 `SUPPORTED_PLATFORM_IDS`、`platform_id()` 和 `executable_name()` 中；离线公开 `assemble_package()` 仅接受 macOS ARM64 与 Kylin V10 ARM64。Windows 请求在创建输出目录前以 `ValueError` 停止，无法生成公开包或 accepted manifest。
2. 在线与离线 POSIX launcher 在读取平台状态前使用 POSIX awk 完整校验 JSON。合法 JSON 后追加文本、截断末尾和损坏尾部均以退出码 3 及 `WXDF-E-MANIFEST-INVALID` 停止，且没有创建缓存、下载制品或执行 runtime。
3. `unexpected_styles` 缺失、`null`、字符串、布尔值或负数时，公开摘要将 `unexpected_styles_count` 设为 `null`，强制 `manual_review_required=true`，并加入 `WXDF-E-AUDIT-EVIDENCE-MISSING`。三份 Skill 明确规定只有整数 `0` 可以交付。

## Standards 复审修复

复审补充的两个边界已闭环：

1. 两套 POSIX launcher 在 awk JSON 解析前通过 `od -An -v -t u1` 和 awk 检查全部字节。合法 JSON 后附 NUL 与垃圾数据时，以退出码 3 及 `WXDF-E-MANIFEST-INVALID` 停止，缓存、下载与 runtime 均未触发。
2. `build_distribution.py --compile-only` 在 standalone 编译完成后输出并返回 `.dist` 目录，不进入公开包组装。Windows 历史入口使用该模式，移除了 `--archive` 和公开 package smoke。README 与开发流程将公开包合同限定为 macOS ARM64 和 Kylin V10 ARM64。
