## 实施摘要

### 单一默认工厂

`build_native_v2_registry()` 只有一种形状：先执行拥有解析、范围、结构、保护内容、列表、表格、题注与附录的八个语义 Module，再执行构造 source AST、聚合 CandidateSet、裁决、提交事务、规范化、渲染、审计与发布的八个阶段链 Module，合计十六个 Module。默认调用即返回完整原生链，不再存在八模块浅层形状。

`semantic_modules` 参数保留为注入接缝，用于替换默认语义集；空值与缺省值都回落到注册的默认语义集，不会产生浅层链。`bindings` 参数按 Module 标识替换任意注册 Module 的进程内实现，未绑定的 Module 保留注册实现。

`ConversionKernel._convert_modular_native_v2` 使用同一个默认调用，Kernel 不再显式拼装另一种形状。`_native_preflight` 的默认注册表同源。

### 执行计划可观察

`NATIVE_STAGE_CHAIN_MODULE_IDS` 已删除，`_native_execution_plan_report` 不再过滤，报告按实际计划与执行顺序列出全部十六个已执行 Module。`report["execution_plan"]["modules"]` 的模块标识序列与 `report["native_module_evidence"]` 的插入顺序一致，证据的 `order` 为连续的 `0` 到 `15`。

### Kernel 收口

`_convert_modular_native_v2` 只做：构建请求级服务（`SourceStore`、`MetricsCollector`、staging 路径）、请求执行计划、执行计划、把终态产物翻译为 `RunResult`。

`_execute_native_stage_chain` 与其内联的八个阶段实现全部移入 `wxdf.builtin_modules`，作为 `native_stage_executors()` 注册。Kernel 中不再出现解析、范围、结构、保护内容、列表、附录、表格或题注识别调用。保留的两处 `semantics` 导入是 AST 构造与列表物化的兼容接缝，属于构造而非识别。

`_convert_modular_native_experimental` 也改为注册 Module 链，Kernel 不再直接调用 `parse` 与 `analyze_lists`。该链路只为基准测试保留。

### 注册 Module 的真实语义所有权

`native_semantic_modules()` 返回八个语义 Module，各自调用既有 `semantics` 函数并把真实产物发布到能力总线：

| Module | 产出能力 |
| :--- | :--- |
| `source-facts-parser` | `source_facts`、`source_facts_summary`、`source_facts_digest` |
| `source-region` | `source_regions`、`source_region_candidates`、`source_region` |
| `document-structure` | `document_structure_candidates`、`document_structure` |
| `protected-content` | `protected_content_candidates`、`protected_content` |
| `list-semantics` | `list_semantics_result`、`list_semantics_candidates`、`list_item_map`、`list_semantics` |
| `table-semantics` | `table_semantics_result`、`table_semantics_candidates`、`table_semantics` |
| `caption-semantics` | `caption_semantics_result`、`caption_semantics_candidates`、`caption_semantics` |
| `appendix-semantics` | `appendix_semantics_result`、`appendix_semantics_candidates`、`appendix_semantics` |

阶段链的 `native-source-parser` 构造 `source_ast`，`native-candidate-set` 从总线读取七个语义 Module 的候选产出并追加账本修订，`native-resolver` 消费该候选集，`native-transaction` 消费裁决集与 source AST。Kernel 不再传入任何预计算候选列表。

### Registry 契约强制

`ModuleExecutionContext` 通过 `begin_module`、`require`、`provide`、`end_module` 观察当前 Module 真正读取和写入的能力。`ModuleRegistry.execute` 按执行计划冻结的顺序派发，并拒绝：未注册 Module、读取未声明能力、读取不可用能力、写入未声明能力、成功结束但缺少已声明产出。

失败策略按描述符确定性执行：`fail` 立即重抛；`warn` 记录 `warned` 并继续；`skip` 记录 `skipped` 并继续；`fallback` 在注册了 `fallback` 回调时执行回调并重新强制合同，未注册回调时按 `fail` 处理。

`RegisteredModule(descriptor, execute)` 保持源码兼容，新增可选字段 `fallback`，默认 `None`。

## 限制与风险

- `bindings` 现在按 Module 标识替换任意注册 Module 的实现。这是契约测试的注入接缝，生产 Kernel 不传该参数
- 原生预检不再传入 `node_kinds`，因为 source AST 现在由注册 Module 生成。所有阶段链 Module 都声明支持完整节点类型集合，该检查在原生链上不会触发
- `ConversionKernel._facts_to_ast` 与 `_materialize_list_semantics` 只能保留为委托接缝，调用方分布在授权范围之外
- `_convert_modular` 的 legacy full rules 适配器路径仍自建注册表。该路径属于 T08 的移除范围，本工单未改动其形状
- 删除 `_convert_modular_native_experimental` 中 Kernel 侧的识别调用后，为基准测试改以注册 Module 链实现，行为与报告键保持一致
