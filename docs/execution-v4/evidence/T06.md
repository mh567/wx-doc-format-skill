# T06 CLI 默认切换和旧检查点策略证据

## 状态

T06 已按测试驱动方式完成。公开 CLI 无需架构参数即可进入 native v2 主链，报告和新检查点统一记录 canonical profile `wx-default-v2`。显式 legacy 诊断入口保留，检查点恢复按版本和身份执行迁移或结构化拒绝。

## 实现边界

1. `scripts/main.py` 将默认 CLI 身份切换为 `modular / native-v2 / wx-default-v2`，补充帮助文本、严格三元组合校验、旧检查点版本拒绝及 native Markdown 报告写出。
2. `scripts/wxdf/kernel.py` 将报告、执行计划及 Checkpoint 2.0 的 profile 统一为 `wx-default-v2`，恢复前锁定 pipeline、modular profile 和 list policy，并原子迁移过渡期顶层 profile literal。
3. 主 Codex 在真实黄金样本 RED 后授权扩展 `scripts/wxdf/rendering.py`。该文件只在非 layout 表格单元格写入段落时选择 `表正文`，没有移动现有表格规范化步骤。
4. 测试改动限定在 CLI、恢复、兼容、渲染和既有默认值断言。冻结文件 `tests/test_native_skill_cutover.py` 未修改。

## 兼容矩阵

| 输入或状态 | 处理结果 | 稳定身份或错误 |
| --- | --- | --- |
| CLI 未传 pipeline、profile、list policy | 接受并运行 native 主链 | `modular / native-v2 / wx-default-v2` |
| 显式 legacy 诊断入口 | 仅接受完整 legacy 三元组 | `legacy / legacy-full-v1 / legacy` |
| modular 与 legacy profile 或 policy 交叉组合 | argparse 拒绝，退出码 2 | `modular pipeline requires ...` |
| legacy 与 native profile 或 policy 交叉组合 | argparse 拒绝，退出码 2 | `legacy diagnostic pipeline requires ...` |
| Checkpoint schema 2.0，canonical 身份 | 接受并按检查点配置恢复 | 顶层 profile `wx-default-v2` |
| Checkpoint schema 2.0，顶层 profile 为 `wx_full_rules-native-v2` | 写入响应前原子迁移并继续 | 迁移为 `wx-default-v2` |
| Checkpoint schema 2.0，pipeline、modular profile 或 list policy 漂移 | 写入响应前拒绝 | `checkpoint_pipeline_mismatch`、`checkpoint_profile_mismatch` 或 `checkpoint_list_policy_mismatch` |
| 旧 file protocol 1.0 | 结构化拒绝 | `LEGACY_CHECKPOINT_UNSUPPORTED` |
| 未知 checkpoint schema | 结构化拒绝 | `CHECKPOINT_SCHEMA_UNSUPPORTED` |
| 无可识别版本的 run.json | 结构化拒绝 | `CHECKPOINT_FORMAT_UNSUPPORTED` |

过渡期 literal 仅允许出现在 Checkpoint 2.0 顶层 `profile`。检查点配置仍须完整匹配 `modular / native-v2 / wx-default-v2`。新检查点及新报告不再写入该 literal。
