## 范围与最终边界

1. `ConversionKernel` 只接受 `modular` 与 `wx-default-v2`，并直接编排 native-v2。构造器不再接受 `legacy_runner` 或 `modular_runner`，旧 `_convert_modular` 转接层已经删除。
2. `scripts/main.py` 删除 `_legacy_adapter_argv` 与 `_run_legacy_full_adapter`。默认转换、命令增强、文件请求和恢复全部进入 native-v2 Kernel。
3. 开发源码 CLI 保留完整的 `legacy`、`legacy-full-v1`、`legacy` 诊断三元组，维持 T06 开发诊断兼容。设置 `WX_DOC_FORMAT_RELEASE=1` 后，任一旧值都在旧 helper 调用前以 argparse 退出码 2 和稳定码 `LEGACY_MODE_UNAVAILABLE` 拒绝。
4. `scripts/wxdf/legacy_pipeline.py` 与 `scripts/wxdf/legacy_capability.py` 已删除。`builtin_modules.py` 同时删除 legacy full adapter、source projection 转接、equivalence 转接和实验模块链。
5. `wxdf.migration` 保留为开发侧独立旧数据迁移工具。它不进入默认执行计划，也不进入发布模块清单。
6. Nuitka 使用 32 个显式 `--include-module` 参数构建真实 native 依赖集，不再使用递归 `--include-package`。构建命令对 `wxdf.migration`、`wxdf.legacy_*`、退役桥接模块和退役根模块设置 nofollow。
7. 编译报告使用 XML 元素解析，只把真实 `<module>` 元素计入 runtime 模块集合。实际出现的 forbidden、missing 或 unexpected 模块进入 manifest 的对应字段，并令 `module_set_status=mismatch`。
8. distribution smoke 只接受 `modular_pure`、`modular_online`、`modular_file`、`modular_review` 四个精确模式。任意 legacy 模块、migration 模块、legacy 模式或模块集合不一致均稳定拒绝，错误包含违规字面量。

## 删除与覆盖保留

删除的测试只覆盖已退役接口，包括 LegacyCapability 翻译、LegacyPipeline 包装器、Kernel runner 注入、full legacy adapter、source projection 转接和 equivalence 转接。以下原生行为覆盖继续保留或补强：

1. native Markdown 与 DOCX 解析、结构、列表、题注、表格、附录、渲染和报告。
2. ModuleRegistry、native 执行计划、命令增强、文件协议、checkpoint、resume 和 review。
3. CandidateSet 经 resolver 到 transaction commit 的完整公共 seam。
4. source reference 的内容哈希或 span 在提议后变化时，transaction 以 `TransactionConflict: source reference precondition failed` 拒绝，AST 快照保持不变。
5. 默认、命令增强、文件请求和恢复的子进程调用图均不尝试导入 `docx_pipeline`、`md_pipeline`、`model_normalization`、`template_finalizer`、`docx_render`、`word_model_renderer`、`wxdf.legacy_pipeline` 或 `wxdf.legacy_capability`。
