## 双轨审查修复

双轨审查指出运行模式公开面和编译证据链仍有 legacy 与静默回退风险。本修复在既有接口处收口：

1. `review.mode_manifest()` 只返回 modular pure、online、file、review 四项，并保留 T03、T04、T05 entrypoint 合同。
2. `registry.build_plan()` 默认使用 modular 与 wx-default-v2，只接受这一组合。开发 legacy CLI 继续通过独立诊断路径运行。
3. `wxdf.semantics.compat` 已从源码、语义包导出和发布模块清单删除。两个仅验证 `collect_compat_candidates` 的测试同步删除，resolver 原生行为测试继续保留。
4. distribution 与 review 两个公开 mode manifest 增加跨模块一致性测试，重复常量发生漂移时测试立即失败。
5. 缺失编译报告、非法 XML、合法 XML 中无 wxdf `<module>` 均明确失败。runtime manifest writer 只接受真实非空报告，并固定记录 `runtime_evidence=compilation_report`。
6. 离线公开组装在创建输出目录前读取并验证 runtime manifest。证据类型、模块状态、源码与 runtime 集合，以及 forbidden、missing、unexpected 字段均须满足精确合同。
7. Nuitka、modular distribution 与 T07 的 fake runtime helper 均写入明确的 compilation report manifest。生产组装逻辑没有测试回退路径。

## 第二轮双轨复审修复

第二轮复审确认上一轮 runtime manifest 仍可由手写 JSON 冒充 compilation report 证据。本轮将 XML 与 manifest 组成不可分离的组装证据：

1. build writer 将真实非空 Nuitka XML 复制到 dist 内固定文件名 `wxdf-compilation-report.xml`，runtime manifest 同时记录该文件名和 SHA256。
2. `assemble_package()` 在创建输出目录前重新读取固定 XML，校验文件存在、SHA256、XML 语法和真实 wxdf `<module>` 集合。报告中的 forbidden、missing 或 unexpected 模块均阻止组包。
3. manifest 的 `source_modules`、`runtime_modules` 和 XML 实际模块必须共同等于当前 31 项 release module set。forbidden、missing、unexpected 字段必须为空。
4. `review.mode_manifest()` 是四个 native 模式的唯一权威定义。`build_distribution.MODULAR_OPEN_MODES` 与每份新 manifest 均从该函数派生，构建文件不再维护第二份模式字面量。
5. 组包入口要求 `open_modes` 与权威 manifest 深度相等，要求 `contract_versions` 与预期集合深度相等。legacy 模式、缺模式、多模式、空 mode 合同、缺 contract version 或篡改版本均停止。
6. modular、Nuitka 和 T07 的 fake runtime 夹具均创建真实最小 XML，并调用 production writer 生成带哈希的 manifest。攻击测试只在生产 writer 完成后篡改成对证据。

## 第三轮 Standards 复审修复

第三轮复审要求将 compilation report 的文件完整性校验扩展为真实成功 standalone 报告身份校验，并删除 smoke 中第二份模式名称真源。本轮在既有公开 seam 完成以下收口：
