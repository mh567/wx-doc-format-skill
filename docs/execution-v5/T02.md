# T02 语义归属与工厂收敛

## 分工

由 Command Code 协同多个智能体实施；concept 归属与 interface 由架构智能体定案，实现与定向测试由一个智能体承担，独立审查与复审由另一个智能体承担。

## 范围

- `scripts/wxdf/semantic_modules.py`
- `scripts/wxdf/semantics/lists.py`、`captions.py`、`tables.py`、`appendices.py`、`source_ast.py`
- `scripts/wxdf/semantics/paragraphs.py`、`source_projection.py`
- `scripts/wxdf/native_stages.py` 的候选基线调用
- 对应测试与 `evidence/T02.md`

## 依赖

无。

## 工作

1. 每个 `*_module()` 工厂收敛为单一存活臂，删除 `native` 与 `protect_semantics` 死分支。
2. 每个 concept 由一个文件同时拥有 facts 到 semantics 到 candidates，暴露一个 interface 返回 `{result, candidates}`。
3. 下游 `paragraphs`、`source_projection` 与 `captions` 内部改为 require 已发布的 `*_result`，禁止重算。
4. list item map owner 并入本票。由 list recognizer 拥有并供 appendix 读取，使 `list_item_map` capability 有真实消费方。

## 验收

- 工厂无死分支，只产出一条 descriptor 形状。
- 同一 `*_result` 不在多处独立重算。
- `list_item_map` 有真实消费方。
- 全量测试与真实 Markdown、真实 DOCX 转换通过。

## 红灯

断言给定既有 result 时下游不再调用 facts 侧 recognizer；断言工厂只产出一条 descriptor 形状。初始运行应失败。
