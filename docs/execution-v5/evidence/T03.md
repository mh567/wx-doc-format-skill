# T03 保护策略 owner

## 实施摘要

保护策略收敛到 `scripts/wxdf/semantics/protected.py` 单一 owner。`lists.py` 不再携带任何日期、版本、API、手工标题与代码样式正则或标签常量。

### 归属定案

- `protected.py` 新增 `protected_code_style(style)` 与 `protected_text_reason(text, evidence)`，由它们唯一持有 `_DATE_RE`、`_VERSION_RE`、`_VERSION_CONTEXT_RE`、`_API_RE`、`_HTTP_API_RE`、`_API_LABELS`、`_MANUAL_HEADING_RE`、`_CODE_STYLE_RE`。
- `protected_unit_semantics` 保留为保护判定的 owner 入口，改由上述两个 helper 产出 code 样式与文本原因的裁决。
- `lists.py` 删除同名正则与 `_API_LABELS`，改为 `from .protected import protected_code_style, protected_text_reason`，`_is_protected` 只在自身列表语境下复用同一策略。

### 行为保持

- `lists._is_protected` 的判定顺序与原因字符串保持不变，包括 code 样式优先、`source_protected`、已检出编号的提前放行、可见标记分支的短路语义、`note_evidence` 与最终编号放行。
- `protected_unit_semantics` 的返回形状与原因不变，包括 `formula_opaque` 仅在无可见标记短路时参与判定。
- 未重命名任何稳定接口。`protected_unit_semantics`、`collect_protected_candidates`、`analyze_lists`、`recognize_list_semantics` 名称与签名不变。
- 新增 `tests/test_t03_protection_owner.py`，并按既有工单惯例在 `.gitignore` 追加 `!tests/test_t03_protection_owner.py` 白名单，使其纳入版本管理。

### 决策记录

可见标记分支在保护判定中具有终局性，因此 `protected_text_reason` 在标记存在且未命中时返回 `None` 表示终局，调用方各自复现既有的短路分支。日期与版本的判定顺序在两端保持一致，避免同一文本在两侧给出不同原因。
