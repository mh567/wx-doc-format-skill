# T02 语义归属与工厂收敛

## 实施摘要

每个 concept 收敛为单一 owner，下游读取已发布结果，list item map 获得真实消费方。

### Owner interface：facts 到 semantics 到 candidates

- `semantics/lists.py` 新增 `recognize_list_semantics(facts, source_ast)`，返回 `{result, candidates, item_map}`。`item_map` 记录每个源列表项归属的 native list container。
- `semantics/tables.py` 新增 `recognize_table_semantics(facts, source_ast)`，返回 `{result, candidates}`。
- `semantics/captions.py` 新增 `recognize_caption_semantics(facts, source_ast, table_semantics_result)`，返回 `{result, candidates}`。
- `semantics/appendices.py` 新增 `recognize_appendix_semantics(facts, source_ast, item_map)`，返回 `{result, candidates}`。原有的细粒度函数保持原名与签名可继续使用。

### 工厂收敛为单一存活臂

`semantic_modules.py` 中 `source_facts_module`、`document_structure_module`、`list_semantics_module`、`table_semantics_module`、`caption_semantics_module`、`appendix_semantics_module` 均删除 `native` 与 `protect_semantics` 形参，只保留原先 `native=True` 与 `protect_semantics=True` 的存活分支。`native_semantic_modules()` 直接调用无参工厂。每个 concept module 都同时发布 `*_result` 与 `*_candidates`。

### 下游读取已发布结果

- `semantics/captions.py` 的 `_authored_caption_candidates` 改为接收已发布的 caption result，不再在内部调用 `collect_source_caption_semantics` 与 `collect_source_table_semantics`。`collect_caption_candidates(ast, facts, *, caption_semantics=None)` 在未传入时保留一次回退计算，供直接调用的测试使用。
- `semantics/paragraphs.py` 的 `collect_paragraph_candidates(facts, source_ast, *, caption_semantics_result=None)` 优先读取已发布 caption result，不再重算 caption 与 table semantics。
- `semantics/source_projection.py` 的 `project_source_facts(facts, regions, *, caption_semantics=None, appendix_semantics=None)` 在调用方传入已发布结果时按 owner 归属判定 caption 与 appendix，未覆盖的节点保留本地 SourceFacts 解析。
- `native_stages.py` 的候选基线调用点把已发布的 `caption_semantics_result` 传给 `collect_paragraph_candidates`。

### list item map owner 并入

list semantics 拥有并发布 `list_item_map`，appendix semantics 通过 `c.require("list_item_map")` 读取它。`prepare_native_appendix_semantics` 与 `collect_native_appendix_candidates` 改为从该 map 推导 item 到 list container 的映射，替换原先从 list result 重建的映射。真实 DOCX 运行时 `appendix-semantics` 的 consumed 列表包含 `list_item_map`。

### 行为保持

现有细粒度函数未改名。`materialize_list_semantics`、`collect_caption_candidates`、`collect_paragraph_candidates`、`prepare_native_appendix_semantics`、`collect_native_appendix_candidates`、`project_source_facts` 的默认调用路径输出不变。

## 开放项

- `native_stages._native_candidate_set` 通过 `context.artifacts.get("caption_semantics_result")` 读取已发布结果再传给 `collect_paragraph_candidates`。改用 `context.require` 需要把该 capability 加入 `native-candidate-set` 的 descriptor requires，而 descriptor 由 `registry.py` 定义且不在本工单范围（T04 拥有注入面收敛）。按名读取不改变静态调用图。
- `source_projection.project_source_facts` 只在调用方传入已发布结果时读取 owner 归属。生产调用点位于 `main.py`，不在本工单范围，故未接线。appendix 与 caption 的 owner 覆盖之外的节点继续使用本地 SourceFacts 解析，这是有意的覆盖差异。
- `semantic_modules.build_native_candidate_baseline` 仍保留 `_compat` 兼容钩子与按名回查，这是 T04 的范围。本工单仅在其中复用已发布的 caption result 以避免重复重算。
- `list_item_map` 的取值语义由「源列表项到 native list item」调整为「源列表项到 native list container」，仅影响先前无消费方的该 capability，形状仍为 mapping 2.0。
