# T06 事务证明收敛

## 实施摘要

事务证明的构造与校验收敛到 `decision_ledger`，它是账本、response 与 checkpoint 三者的共同锚点。`decision_ledger` 不再重演 `transaction` 的 apply 语义，改为调用 `transaction` 导出的纯判定函数 `revision_applied`。`checkpoint_store` 与 `response_store` 的证明片段删除本地副本，改指向 ledger owner。所有摘要值与 checkpoint schema 保持不变。

### 生产代码

- `transaction.py`：新增纯判定函数 `revision_applied(ast, revision, snapshot=None)`，函数体即原 `decision_ledger._revision_applied`，逐字搬运，只改名并补文档串。它报告某个 ledger revision 是否已经与当前 commit 一致，与 `_apply_*` 同处一个 module，因此操作改动只需改一处。函数不修改 `ast` 与 `snapshot`。
- `decision_ledger.py`：
  - 从 `transaction` 导入 `revision_applied`，删除本地 `_revision_applied` 定义，`_replay_snapshot` 内三处调用点改为 `revision_applied`。ledger 不再自带 apply 语义重演。
  - 新增证明 owner：`APPLICATION_FIELDS`、`response_transaction_binding`、`stored_transaction_digests`、`snapshot_transaction_state`、`verify_response_transaction_proof`。前四者分别来自 `response_store._APPLICATION_FIELDS`、`checkpoint_store._response_transaction_binding`、`checkpoint_store._stored_transaction_digests`、`checkpoint_store._snapshot_transaction_state`，逐字搬运。`verify_response_transaction_proof` 把 `complete_pending_response` 内的 response 与 transaction 与 checkpoint 绑定校验收拢为一个函数，抛出 `LedgerError` 且保留原有 code 与消息文本。
  - `ledger_transaction_digests` 与 `_legacy_transaction_digest` 保留原位，账本摘要规则本来就是 owner 自身职责。
- `checkpoint_store.py`：删除 `_response_transaction_binding`、`_stored_transaction_digests`、`_snapshot_transaction_state` 三个本地定义，改为 `from .decision_ledger import response_transaction_binding, snapshot_transaction_state, stored_transaction_digests`。`complete_native_checkpoint`、`_migrate_transaction_digest_version`、`_validate_for_store`、`load_checkpoint` 内调用点全部改指向 ledger owner。
- `response_store.py`：删除本地 `_APPLICATION_FIELDS`，改为 `from .decision_ledger import APPLICATION_FIELDS, LedgerError, verify_response_transaction_proof`，`response_digest` 与 `complete_pending_response` 引用 owner 常量。`complete_pending_response` 的 response 与 transaction 与 checkpoint 绑定校验由 `verify_response_transaction_proof` 承担，`LedgerError` 就地转成 `CheckpointError`，code 与消息文本不变。
