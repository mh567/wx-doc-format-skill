# T07 Checkpoint 拆分与 response_store seam

## 实施摘要

request-append journal 抽成独立 module，checkpoint 与 response 之间的反向 re-export 与 import 环一并封口。journal 文件格式、checkpoint schema、response 身份规则和全部稳定入口保持不变。

### 生产代码

- `request_append.py`（新增）：承载跨进程文件锁与 write-ahead journal 及其崩溃恢复。逐字搬运 `_request_append_journal_path`、`_bytes_digest`、`_replace_bytes`、`_exclusive_file_lock`、`_recover_native_request_append`、`append_native_waiting_requests`、`_append_native_waiting_requests_locked`。journal schema 保持 `1.0`，journal 文件名后缀保持 `.request-append.journal`，锁文件后缀保持 `.request-append.lock` 与 `.append.lock`。module 只 eager 导入 `wxdf.digest`；`save_checkpoint` 与 `CheckpointError` 取自 `checkpoint_store`，`request_digest` 取自 `response_store`，两者都放在需要它们的函数内部，导入本 module 不触发 import 环。
- `checkpoint_store.py`：
  - 顶部删除 `from .response_store import content_digest, request_digest, response_digest`，改为 `from .request_append import _exclusive_file_lock, _recover_native_request_append, append_native_waiting_requests`。`append_native_waiting_requests` 仍由 checkpoint 暴露，因为 `kernel.py` 在调用时从 checkpoint 绑定该名字，且本轮不改 kernel。
  - 删除文件底部的 `from .response_store import (...)` 反向 re-export，`__all__` 去掉 `apply_response`、`complete_pending_response`、`content_digest`、`record_response`、`request_digest`、`response_digest` 六个符号。
  - 删除随 journal 迁出的锁与恢复实现，删除因此不再使用的 `base64`、`os`、`contextmanager`、`fcntl`、`msvcrt` 导入。`hashlib`、`json`、`copy` 仍在使用，保留。
  - `_validate_for_store` 提升为公开 `validate_checkpoint_for_store`，`_validate_embedded_fingerprints` 提升为公开 `validate_embedded_fingerprints`，调用点同步更新，两者进入 `__all__`。
  - `validate_embedded_fingerprints` 内部按需导入 `request_digest`、`response_digest`，`prepare_native_resume` 内部按需导入 `record_response`。checkpoint 在 module 级别不再导入 response_store，依赖方向变为单向。
  - persistence 与 `prepare_native_resume`、`complete_native_checkpoint`、`write_native_waiting_checkpoint` 保持 checkpoint 的深 interface。
- `response_store.py`：删除 `_store()` 懒取 module 的手法，改为顶部 `from .checkpoint_store import CheckpointError, save_checkpoint, validate_checkpoint_for_store, validate_embedded_fingerprints`。`CheckpointError`、`save_checkpoint` 为公开 API，两个校验入口为本轮新提升的公开 API。函数逐字保留原语义与错误 code，`__all__` 不变。
- legacy digest 迁移保持隔离的私有 helper `_migrate_transaction_digest_version` 及其只读依赖 `_validate_legacy_checkpoint_replay`，仍留在 checkpoint 内。

### 导入方向

module 级依赖为单向：`response_store` 到 `checkpoint_store` 到 `request_append` 到 `digest`。`request_append` 与 `checkpoint_store` 之间的向上调用放在函数内部，不构成 module 级环。

## 开放项

- 独立审查与复审由另一个智能体承担，尚未执行；本文件记录实现侧结果。
- `checkpoint_store` 仍暴露 `append_native_waiting_requests`，并以私有名字导入 `_exclusive_file_lock`、`_recover_native_request_append`。理由：`kernel.py` 在调用时从 checkpoint 绑定 journal 入口且本轮不改 kernel；`prepare_native_resume` 属于 checkpoint 深 interface，它在恢复时仍需持有 journal 锁并执行 journal 恢复。该实现与既有 `checkpoint_store` 从 `decision_ledger` 导入私有 `_replay_snapshot` 的跨 module 风格一致。
- `request_append` 自带 `_path` 小助手，与 checkpoint 内同名助手重复。该助手不属于身份规则，重复成本为一行，为避免额外私有跨 module 导入而保留。
- `checkpoint_store` 对 `response_store` 保留三处函数内按需导入：`prepare_native_resume` 的 `record_response`，`validate_embedded_fingerprints` 的 `request_digest` 与 `response_digest`。三者都是 response_store 的公开名字，且 checkpoint 在 module 级别不再导入 response_store，导入环已消除。将这两处依赖彻底移除需要移动 `validate_embedded_fingerprints` 或持久化入口，会重新形成环，故不纳入本轮。
- `checkpoint_store` 的 `Callable` 导入沿用现状，未在本轮处理。
- 未改动 `docs/execution-v5/status.json`，未提交，改动保留在工作区。未触碰 `scripts/wxdf/semantics/**`、`kernel.py`、`registry.py`、`run_result.py`、`digest.py`、`native_stages.py`、`semantic_modules.py`、`normalization.py`、`resolver.py`、`transaction.py`、`decision_ledger.py`。
