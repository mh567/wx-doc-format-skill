# T01 证据：Kernel 静态方法归位

## 范围

- 工单：T01
- 目标：把 kernel 的 artifact 翻译静态方法移到产物的 owner module，删除死代码，kernel 只留 lifecycle。
- 固定基线：`f902032`（本执行包提交）
- 未改动：稳定 CLI 参数、公开报告合同、`_build/`、`paseo.json` 及无关用户改动。

## 实施摘要

1. 删除死方法 `_native_should_block_publish`，实际检查已内联在 `native_stages.py`。
2. 删除兼容静态方法 `_facts_to_ast`、`_materialize_list_semantics`，调用方改为直接驱动 `semantics/source_ast`。
3. `_native_source_type` 迁为 `parsers.detect_source_type`。
4. `_native_preflight`、`_native_execution_plan_report`、`_native_capability_status`、`_native_checkpoint_modules` 迁入 `registry`，另含 `capability_migration_report`、`build_native_run_result`。
5. `_native_ledger_replay_report` 迁为 `decision_ledger.ledger_replay_report`。
6. `_lock_native_checkpoint_identity` 迁为 `checkpoint_store.lock_native_checkpoint_identity`。
7. `_native_v2_run_result` 按 artifact owner 拆分，kernel 只保留 `convert` 与 `_convert_modular_native_v2`。

`scripts/wxdf/kernel.py` 由约 1024 行收缩到只剩两个 lifecycle 方法。

- Standards，已修复：`registry.build_native_run_result` 依赖 `kernel.RunResult`，形成 registry 到 kernel 的反向依赖。现 `ConversionRequest` 与 `RunResult` 迁入新 module `scripts/wxdf/run_result.py`，`kernel` 与 `registry` 均从该 module 导入，反向依赖消除。

- Standards，记录未修复：`capability_status` 参数结伴穿行；`decision_ledger.ledger_replay_report` 直接读 `context.artifacts`。
